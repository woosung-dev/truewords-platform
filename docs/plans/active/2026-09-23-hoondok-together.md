# PLAN-HD-009 — 함께 읽는 사람들 1단계: 익명 숫자

- 착수 2026-09-23. 기준 main `5b5419a`. 브랜치 `feat/hoondok-together-count`(로컬 커밋, 푸시·PR·배포는 별도 승인).
- 화면: 홈(`SCR-PWA-002`) "함께 읽는 사람들" 섹션 첫 카드, 훈독하기(`/hoondok/read`) 완료 영역. 참고 프로토타입은 `hoondok-ds/app.html` 의 `screen=today` 익명 카드와 `screen=read&done=1` `.tg-after` (DEC-PWA-023 초안).
- API: [`API-HD-029`](../../specs/api/hoondok-api.md#api-hd-029-get-hoondoktodaytogether) `GET /hoondok/today/together`.
- 표기: 라벨 없는 문장은 코드로 확인한 사실. `[가정]` 은 검증이 필요한 추론, `[결정]` 은 이 계획에서 정한 것, `[확인 필요]` 는 사용자·외부 결정.

## 1. 목적

혼자 읽는 훈독에 "오늘 같은 말씀을 읽은 식구가 있다"는 감각만 더한다. 누가 읽었는지, 누가 안 읽었는지는 보이지 않는다. 비교·재촉·순위를 만들지 않는 가장 작은 단계다.

- `[결정]` **문구에서 "새벽" 을 뺀다.** 프로토타입 원문은 "오늘 새벽 함께 읽은 식구 N명" 이지만 숫자는 하루(KST 00:00~24:00) 전체 집계라 "새벽" 은 사실과 다르다. 홈 카드는 "오늘 함께 읽은 식구 N명", 보조줄은 "같은 말씀을 읽었어요 · 누가 읽었는지는 보이지 않아요"(숨김일 때도 같은 보조줄). 완료 영역은 "당신까지 N명이 함께 읽었어요" / "오늘도 식구들과 함께 읽었어요".
- `[결정]` 임계값은 설정 `HOONDOK_TOGETHER_MIN_COUNT`(기본 10), 캐시는 `HOONDOK_TOGETHER_CACHE_SECONDS`(기본 60, 0 이면 끔). 응답의 `threshold` 로 화면이 기준을 안다.
- `[결정]` `mission_logs(mission_date, kind)` 인덱스를 추가한다(alembic `q2b3c4d5e6f7`, additive). 기존 unique 는 `user_id` 가 선두라 날짜 조건에 쓰이지 않는다.

## 4. 인수 조건

- [x] 완료자 0·9명 → `count=null`, `is_shown=false`. 10명 → `count=10`, `is_shown=true` (pytest)
- [x] 같은 사용자가 read·pray·study 를 모두 해도 1명, 다른 kind·어제·내일·탈퇴 사용자는 빠진다 (pytest)
- [x] KST 경계: UTC 14:59:59 는 그날, UTC 15:00 은 다음 날로 센다 (pytest)
- [x] 인증 없이 200, 캐시 60초 안에는 같은 값·만료 뒤 재집계·0 이면 매번 집계 (pytest)
- [x] 홈: 기준 이상이면 "오늘 함께 읽은 식구 1,284명"(천 단위 쉼표), 미만이면 대체 문구, 로딩은 스켈레톤, 오류면 섹션째 숨김, 링크·모임·"아직" 없음 (Vitest)
- [x] 완료 영역: "당신까지 N명이 함께 읽었어요" / 대체 문구. 서버 집계에 없는 완료(비로그인·저장 실패)는 숫자가 있어도 "당신까지" 를 쓰지 않는다 (Vitest)
- [x] 홈 e2e: 카드 1장, API 값과 화면 문구가 맞는다
- [x] `pnpm hoondok:check` 통과(토큰 밖 hex 0)

`[가정]` 서버 캐시(60초)와 워커별 메모리 때문에 방금 완료한 본인이 숫자에 아직 없을 수 있다. 화면은 +1 보정을 하지 않고 서버 값을 그대로 쓴다 — 보정은 캐시 적중 여부를 모르는 클라이언트가 틀린 숫자를 만들 위험이 더 크다. 완료 직후 `PROGRESS_KEYS` 무효화로 다시 읽기는 한다.

`[가정]` 비로그인 로컬 완료는 서버에 기록이 없어 숫자에 포함되지 않는다. 로그인 소급(sync) 뒤에는 포함된다.

## 5. 2단계 예정 범위 (상세 설계는 후속)

모임(리더가 만들고 초대 코드로 참여) · 초대 · 모임 안 한 줄 나눔 · 반응 · 모임 정성(모임 전체 N일차) · 공식 정성. 원칙은 1단계와 같다 — 완료한 사람만 그리고, 미완료자 이름·상태·재촉 버튼을 만들지 않는다. 홈 "내 모임" 링크·모임 카드·"모임 만들기/참여" 진입은 2단계에서 연다.
