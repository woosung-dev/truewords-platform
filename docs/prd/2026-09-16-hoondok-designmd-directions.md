## 0. 이 비교가 앞선 비교와 다른 점

`DES-PWA-004`는 디자인 **도구** 3종이 자유롭게 그린 시안이었다. 이번에는 실제 브랜드가 공개한 **디자인 규칙 문서(DESIGN.md)** 를 읽고 훈독 도메인으로 번역했다. 브랜드 로고·이름·상징은 하나도 가져오지 않았고, 여백 총량·타이포 위계·색 역할 배분·형태 체계만 가져왔다.

구조도 다르다. 7안 모두 **같은 마크업 한 벌(`app.html`)과 같은 베이스 CSS(`hoondok.css`)** 를 쓰고, 다른 것은 얹은 테마 CSS 한 장뿐이다. 정보구조·콘텐츠 차이가 0이라 심사가 순수하게 시각 언어만 본다. 폰(390)이 설계 기준이고 PC(1280)는 같은 CSS 의 미디어쿼리가 확장한 결과다.

## 3. 심사 전 손질 (스킬 패스 2회)

심사 캡처 전에 테마 CSS 6장(A 제외)에 두 패스를 돌렸다. 각 패스가 기각한 지적은 CSS 하단 주석 블록에 사유와 함께 남겼다.

| 패스 | 수정 | 기각 | 가장 큰 발견 |
|---|---|---|---|
| `ui-ux-pro-max` (접근성·터치·폭·타이포) | 21 | 2 | E 하단 탭이 딥그린 색면이라 베이스 초록 포커스 링이 **2.16:1** 로 보이지 않았다. 흰 링(12.45:1)으로 교체 |
| `taste-skill` (AI 슬롭 패턴) | 14 | 15 | F today 의 미션 3개가 바로 아래 정성 카드와 면·테두리·모서리가 완전히 같아 위계가 사라졌다. 헤어라인 행으로 내림 |

`ui-ux-pro-max` 패스는 6테마 × 3화면 × 2폭 = 36 조합을 실측했고, 헤더 주석의 대비 수치는 전부 실측과 일치했다. 1280 본문 폭은 폰트를 건드리지 않고 `--measure-read` 만 테마별로 조정해 한글 35~44자 구간에 넣었다.

**7안 공통이라 손대지 않은 것 2건**: `app.html` 의 "이 말씀에 질문하기" 인라인 링크 높이 19.5px, 체크 원(30~32px)·용어 칩(30px) 이 44px 미만. 베이스 마크업·`DES-PWA-003` 소관이며 어떤 안을 고르든 같이 고쳐야 한다.

### 4.2 심사원 3명이 독립적으로 같은 말을 한 것

| 대상 | 3/3 공통 |
|---|---|
| **E 채택 근거** | `e-390-read` 의 딥그린 반전 원문 블록. 권위 3층을 색이 아니라 **바탕의 무게**로 가른 유일한 안. 색각 이상·저조도에서도 "짙은 덩어리 = 공식 원문"이 살아남는다 |
| **C 채택 근거** | 라벤더 AI 콜아웃 + 세리프 원문 + 점선 메모. 3층이 색·서체·형태 세 축으로 동시에 갈린다. `c-1280-words` 읽기 폭(약 40자)이 7안 중 가장 정확하다 |
| **E 수정 필수** | 딥그린 카드 위 골드 `D-14` 가 AA 경계. 하단 딥그린 푸터 띠가 딥그린 탭바와 붙어 짙은 띠 두 겹. 원문이 길어지면 다크 장문 읽기가 50~60대에 부담 → **글자 수 임계치 넘으면 라이트 카드 + 좌측 바로 폴백** 규칙 필요 |

2/3 이 지적: C·D 체크박스가 30px 사각이라 엄지 타깃 부족(§3 의 공통 건). F 의 AI 크림 카드가 페이지 크림과 명도 차가 작아 층 분리가 C·E 보다 무르다. F 요일 칩이 검정 채움 + 테라코타 테두리라 팔레트가 흔들린다.

### 4.3 A 재채점 공개

첫 캡처에서 A 의 훈독하기·원문 화면에 **출처 라인과 `O1 공식 원문` 배지가 통째로 빠져 있었다.** `theme-card.css` 가 홈 첫 요소를 사진으로 두려고 `.lede-src` 를 숨겼는데 화면 구분 없이 전부 숨긴 제작 결함이다(이전 커밋 `4ecf6d0`). today 화면에만 적용되도록 한 줄 고치고 A 캡처 5장을 다시 찍어 3명에게 **A 만** 재채점을 요청했다.

| 심사원 | A 이전 → 이후 | 순위 변화 |
|---|---|---|
| 1 | 65 → 70 (권위층 +6, 접근성 −1) | 5위 유지 |
| 2 | 71 → 77 (권위층 +3, 대상·모바일·접근성 +1씩) | 5위 → 4위 |
| 3 | 68 → 73 (권위층 +4, 접근성 +1) | 4위 유지 |

재채점 후에도 A 는 C·E 와 11점 차다. 결함 수정이 순위 구조를 바꾸지는 않았다. 재채점 기록은 각 `judge-N.md` 하단에 있다.

| "심사 결과를 따르겠다" | **E** 또는 **C** | `DEC-PWA-017` 재결정 + `DES-PWA-003` §1 토큰 교체. E 는 반전 블록 장문 폴백·골드 대비, C 는 라벤더 본문 대비 실측 |
| "감귤 아침 느낌은 지키되 A 보다 나은 걸 원한다" | **F** | 재결정 필요. 칩·선 대비 보강(접근성 13.3) |
| "A 를 유지하고 고친다" | **A + 흡수** | 재결정 없음. §5.3 흡수 후보 적용 + PC 여백 처리 |
| "지금 못 고르겠다" | 보류 | 실제 사용자 3명에게 `*-390-read.jpg` 7장을 보여 준다. 10분이면 된다 |

### 5.3 어떤 안을 고르든 가져올 것

- **E 의 반전 원문 블록** (3/3 추천). A 골격에 이식하면 "AI·메모 둘 다 점선" 문제가 원문 쪽에서 해소된다
- **C 의 AI 콜아웃 이중 라벨** ("AI 설명 · 공식 해설 아님" 내부 + 헤더 우측). 오인 여지가 가장 적다
- **D 의 형태 전용 요일 칩** (채움/링/민 원). 색만으로 상태를 구분하지 않는다는 요건을 공짜로 충족한다
- **B 의 본문 17px 규범**. 30~60대 주 사용자와 방향이 같다

### 5.4 주의

심사원 3명은 모두 **AI** 다. "대상 적합성" 점수는 추론이지 관찰이 아니다. 실제 30~60대 사용자 3명이 7장을 보는 것이 이 점수 전체보다 낫다.

## 6. 제작 기준

- 마크업 한 벌 `app.html`, 베이스 `hoondok.css`, 테마 `theme-*.css`. 테마는 `[data-theme="x"]` 접두 셀렉터로만 덮어쓴다. 마크업·베이스를 복제하지 않는다
- base=390px. 미디어쿼리 없는 규칙이 폰 규칙, `768`·`1024` 에서 확장. 1024 이상에서 하단 탭 → 좌측 레일 전환은 베이스가 한다
- 콘텐츠(말씀·인물·교회·수치)는 예시이며 7안 동일. 사진은 `picsum.photos` 예시
- 렌더 검증: Chromium 390×844·1280×900, 7안 × 3화면, 가로 넘침 0px, JS 오류 0
- **심사 후 발견한 베이스 결함**: 1024px 이상에서 레일이 오른쪽에 붙어 있었다(`hoondok.css` 가 DOM 순서만 바꿔 `main` 뒤의 `nav` 가 우측으로 감. `DES-PWA-003` §4.1 은 좌측 레일). `.nav{order:-1}` 로 수정. 7안 PC 캡처 14장이 모두 우측 레일로 심사됐으나 7안에 동일하게 적용된 조건이라 순위에는 영향이 없다 `[가정]`. A 의 PC 캡처 2장만 재촬영했다
- DESIGN.md 원본은 수정하지 않았다(외부 자료 정책). 번역 근거는 각 CSS 헤더
