- 문서 ID: `DES-PWA-001`
- 작성일: 2026-09-07
- 상태: **사용자 방향 선택 대기** (S2 산출물)
- 입력: [PRD-FFWPU-PWA-001](17-ffwpu-pwa-prd.md), [S0 제품 방향](../research/2026-08-30-pwa-app-direction.md), [초원AI 벤치마크](../research/2026-08-30-chowon-ai-benchmark.md)

## 1. 이 문서가 답하는 질문

"초원AI처럼 우리 웹앱을 만든다면 첫 화면과 정보구조를 어떻게 잡을 것인가." 초원의 5탭(매일 QT · AI 질문 · 성경 · 공동체 · 나의 초원)을 복제하지 않고, S0에서 승인한 포지셔닝(출처 우선 · 용어 맥락 · 가족 실천 · AI 권한 제한 · 비감시)을 각각 다른 축으로 앞세운 세 방향을 같은 예시 데이터로 비교한다.

세 방향 모두 같은 4개 화면(홈 · 질문 · 원문·출처 · 서재/실천)을 갖고, 같은 5개 검증 과업을 수행할 수 있게 만들었다. 다른 것은 **첫 화면이 무엇을 하나만 요구하는가**와 **정보의 밀도·톤**이다.

## 2. 초원 정보구조와의 대응

| 초원AI (공개 스토어 화면) | A 오늘 루틴 | B 출처 서고 | C 가족 실천 |
|---|---|---|---|
| 매일 QT | **오늘** (첫 탭) | 찾기 안의 "오늘 한 문단" 카드 | **오늘** (저녁 훈독) |
| AI 질문 | 찾기 탭 안 질문 | **질문** 탭 (근거 먼저) | 찾기 탭 안 질문 |
| 성경(읽기·역본) | 원문 상세 + 앞뒤 문맥 | **찾기** 첫 탭 + 판본 병기 | 원문 "가정에서 읽기" 모드 |
| 공동체 | 없음 (비범위) | 없음 (비범위) | 나눔 카드만, 가족 초대는 "준비 중" |
| 나의 초원(기록·달란트) | 서재 (점수 없음) | 서재 (출처 한 줄) | 실천 (주간 기록, 점수 없음) |

복제하지 않은 것: 초원의 녹색 팔레트, 카드 배치, 씨앗/나무 성장, 달란트 보상, 연속 기록, 5탭 전체, 공개 커뮤니티.

| 시각 언어 | 밝은 회백 바탕, 코발트 1색, 모서리 16px, IBM Plex Sans KR + Noto Serif KR | 슬레이트 바탕, 테라코타 1색, 모서리 6px, 메타는 IBM Plex Mono | 다크 잠금 테마, 앰버 1색, 모서리 12px, 본문 큰 글씨 22px |

## 4. 추천 `[제안]`

**B(출처 서고)를 정보구조 골격으로 채택하고, A의 "오늘 카드"를 B의 첫 화면 상단에 두는 결합을 추천한다.** C의 "한 줄 실천"은 별도 탭이 아니라 원문·질문 화면의 마지막 행동(컴포넌트)으로 S3에서 흡수한다.

이유:

1. 승인된 차별화 문장의 핵심은 "정확한 출처와 맥락으로 되돌려 보낸다"이며, B는 화자·연도·판본·공식성을 모든 화면의 첫 줄에 둔다. 초원이 이미 점유한 "매일 QT + AI 질문" 정체성과 가장 멀다.
2. 현재 저장소 자산(스트리밍 채팅, 문단 인용, 원문 보기, 대화 기록, 하이브리드 검색)을 가장 많이 재사용한다. A는 매일 편성 운영, C는 공유 권리 원장이 먼저 필요하다.
3. A의 재방문 루프는 B 위에 "오늘 한 문단" 카드 하나로 얹을 수 있다. 반대로 A를 골격으로 두면 오늘 콘텐츠가 없는 날 첫 화면이 비는 실패 상태를 먼저 설계해야 한다.
4. C가 가리키는 가족 실천은 MVP 비범위(가족·소그룹은 권한·아동 보호·운영 책임 확정 뒤)와 맞닿아 있어, 지금은 개인 기록 안의 한 줄 실천으로만 도입하는 편이 안전하다.

사용자가 A를 고르면 편성 운영 주체·주기·대체 콘텐츠 정책을 S3 진입 조건에 추가한다. C를 고르면 공유 카드의 콘텐츠별 공유 권리와 라이트 테마 변형 검증을 S3 진입 조건에 추가한다.

## 5. 세 방향 공통 규칙

프로토타입에서 어느 방향을 골라도 유지되는 규칙이다. PRD의 `REQ-PWA-004/005/006/008/010/012`를 화면 규칙으로 옮긴 것이다.

- 권위 층 4종(AI 설명 · 공식 원문 · 공식 해설 · 내 메모)은 라벨 텍스트와 형태(점선·굵은 왼쪽 선·점선 테두리)로 구분하며 색만으로 구분하지 않는다.
- O1~O5/R 공식성과 검수일은 배지 텍스트로 표시한다. 확인되지 않은 메타데이터는 추정값 대신 "확인되지 않음"으로 둔다.
- 질문은 기본 저장 안 함이며, 저장은 사용자가 고른다. 서재·실천 기록은 기본 비공개다.
- 설치·알림은 첫 읽기 또는 저장 뒤에만 제안하고 잠금 화면 문구는 중립형("오늘의 읽을거리가 준비됐어요")이다.
- 근거가 없으면 "확인할 수 없음"으로 끝내고 원문 검색·공식 문의 경로를 준다. 판본 차이는 나란히 보여 주고 자동으로 한쪽을 고르지 않는다.
- 출석·점수·연속 기록·달란트형 보상을 두지 않는다. 철회된 콘텐츠는 원문을 숨기고 사용자 메모만 남긴다.
- 모든 접점에 "독립 운영 베타 · FFWPU 공식 앱이 아님"을 표시한다.

## 7. 프로토타입 제작 기준

- 모든 말씀·화자·저작물·날짜·검수자·정의는 프로토타입용 예시이며, 실제 정본 텍스트를 전재하지 않았다. 권리 승인 정본은 S7 콘텐츠 적재 전까지 화면에 넣지 않는다.
- 모바일 390px 기준으로 그렸고 비교 보드는 1440px 데스크톱에서 3열, 1279px 이하에서 1열로 접힌다.
- 방향별 테마는 한 가지로 잠갔다(A·B 라이트, C 다크). 라이트/다크 양방향, 큰 글씨·고대비·reduced-motion 상태는 채택안 기준으로 S3 디자인 시스템에서 정의한다.
- 아이콘은 현재 `apps/web`이 쓰는 Lucide를 CDN으로 불러온다. 서체는 Google Fonts의 IBM Plex Sans KR · Noto Serif KR · IBM Plex Mono이며 시스템 폰트 대체 스택을 둔다. 사용자 웹의 현재 paper·brass·Cormorant 조합은 기존 화면 소유이고 신규 PWA의 승인 디자인이 아니므로(UI-WEB-001) 그대로 잇지 않았다.
- 접근성 최소선: 탭은 아이콘+텍스트, 토글·라디오는 `aria-pressed`/`aria-checked`, 포커스 링, 명도 대비는 세 테마 모두 본문 4.5:1 이상을 목표로 골랐다. 실측 감사는 S3에서 한다.

## 8. 다음 단계

1. 사용자가 A·B·C 또는 §4의 결합안 중 하나를 고른다. 고른 방향과 바꾸고 싶은 점을 이 문서 §9에 기록한다.
2. 선택 뒤 S3 진입: 채택안의 색·타이포·간격·모서리·모션 토큰, 라이트/다크, 큰 글씨·고대비, 권위 층 컴포넌트, WCAG 2.2 AA 상태를 `docs/specs/web/`에 정의한다.
3. S3 승인 전에는 `apps/web`의 화면·테마를 바꾸지 않는다(UI-WEB-001 경계).
