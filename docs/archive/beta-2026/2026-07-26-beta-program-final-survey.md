## 0. 설계 전제

### 0-1. 중간미션 폼에서 배운 것

| 관찰된 결함 | 근거 (중간미션 164건) | 최종 설문의 대응 |
|---|---|---|
| **조건부 자유서술 응답률 붕괴** | 필수 객관식 100% vs 조건부 주관식 1~16% (근거 출처 3%, 공격 시도 2%, 막힌 단어 1%) | 조건부 심화 문항 폐지. 자유서술은 전원 필수 1~2개만 |
| **요구사항 받을 칸 부재** | 신우진 — "구글폼에 요청칸이 없어서 여기에 적습니다"라며 *사용 이유* 칸에 북마크 기능을 적음 | 기능 요구 문항을 **독립 필수**로 승격 |
| **자유입력 데이터 오염** | 소속란 "선문대학교 신학과"가 8가지 표기로 난립. 이름도 "하루키/오카야스 하루키", "이채원/이체원", "홍정만/홍정민"으로 흔들려 집계에 수작업 보정 필요 | 이름·소속 전부 드롭다운 |
| **미션 목표 과다** | 목표 18건 대비 인당 평균 6.8건, 달성 3명(9%) | 최종 설문은 1회 응답으로 종료 |

### 0-2. 배포 경로 — 이메일 발송 불가

계정 명단 파일의 헤더는 다음과 같다.

> `ID ( @가 포함된 이메일 형식으로 입력해 주세요. 실제 존재하는 이메일일 필요는 없습니다.)`

**즉 수집된 이메일은 로그인 ID일 뿐 실제 주소가 아니다.** 최종 설문은 단톡방 링크로 배포해야 하고, 응답과 3주간 사용 기록을 잇는 **유일한 조인 키는 이름**이다. 그래서 1번 문항이 반드시 33명 드롭다운이어야 한다.

### 0-3. 설문이 닫아야 할 질문 5개 (보고서 C에서 도출)

로그로는 절대 알 수 없어 설문으로만 확인 가능한 것들이다. 모든 문항은 이 5개 중 하나에 대응한다.

1. **이탈 27%의 이유** — 3주차 활성 인원이 정점 26명에서 20명으로 줄었다. 왜인지 모른다.
2. **평가 버튼을 안 누른 이유** — 평가율 6%. 몰랐는가, 귀찮았는가, 사유 선택이 번거로웠는가.
3. **모드 5종 인지 여부** — 비표준 모드 사용 15%. 선호의 결과인지 무지의 결과인지에 따라 처방이 정반대다.
4. **미션이 없었어도 썼을까** — 자기보고 자발률 79% vs 마감일 10배 진폭(7/20 4건 → 7/21 39건)의 모순.
5. **어떤 기능이 필요한가** — 이번엔 받을 칸을 만들어서 묻는다.

### 0-4. 이미 있는데 사용자가 모르는 기능

설문 설계 중 코드 확인으로 드러난 사실이다. **신규 개발 요구와 발견성 문제를 구분해서 물어야 한다.**

| 기능 | 실제 상태 | 사용자 인식 |
|---|---|---|
| 대화 기록 다시 보기 | **구현 완료, 헤더에 링크 있음** (`/history`) | "전에 질문한 사용기록을 볼 수 있도록 설정되면" — 없는 줄 알았다 |
| 답변 저장(💾) | 백엔드 API 있으나 **UI 미배선** | "저장하거나 북마크 해놓고 볼 수 있게" |
| 👍/👎 리액션 | API·클라이언트 존재, **화면에 미배선** (3주간 0건) | — |
| 다국어 답변 | 미지원. 게다가 **영어 요청이 거부 응답으로 막혔다**(meta 분류) | "봇이 영어나 다른 언어도 대답해줬으면" |

따라서 기능 문항은 "필요한가"만 묻지 않고 **"있는 줄 알았는가"를 함께 묻는 인지도 그리드**를 포함해야 한다.
