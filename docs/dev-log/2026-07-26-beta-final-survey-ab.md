# 체험단 최종 설문 — 발송 확정본 A안 / B안

**작성일** 2026-07-26 · **대상** 체험단 33명 · **본체** 기능 요구 수집형(2안) 채택
**선택 파트** 벤치마킹 비교(3안)를 보너스 미션으로 흡수 · 본체 8분 + 보너스 10분
**검토 기록** [1·2·3안 비교](./2026-07-26-beta-program-final-survey.md) · **근거** 보고서 A/B/C

## 0. 이 문서의 결론 먼저

본체는 2안(기능 요구 수집형)으로 확정한다. 벤치마킹은 **필수에서 빼되 버리지도 않는다.**

A안과 B안은 **벤치마킹을 어떻게 붙이느냐만 다르다.** 본체 17문항은 완전히 동일하다.

| | **A안 · 분기 통합형** | **B안 · 2단 분리형** |
|---|---|---|
| 폼 개수 | **1개** | 2개 (본 설문 + 보너스) |
| 벤치마킹 위치 | 본 설문 끝 → "참여하시겠어요?" 분기 | 별도 폼, 완주자에게 링크 발송 |
| 응답 시점 | 완주 직후 즉시 | 며칠 뒤 (시간 여유 있음) |
| 예상 본체 완주율 | 높음 | 높음 (본체가 더 짧아 보임) |
| 예상 벤치마킹 응답 | **15~25%** | **25~40%** (리마인드 가능) |
| 벤치마킹 응답 품질 | 보통 (그 자리에서 급히) | **높음** (실제로 써보고 답함) |
| 제작 부담 | 폼 1개 + 분기 설정 1회 | 폼 2개 + 완주자 추적 |
| 오늘 발송 가능성 | **매우 높음** | 본 설문은 오늘, 보너스는 2~3일 뒤 |
| **추천도** | **★★★★★** | ★★★★☆ |

### 왜 A안인가

**1. 오늘 발송이 제약 조건이다.** 폼 2개를 오늘 다 만들 필요가 없다는 점에서 B안도 나쁘지 않지만, B안은 "완주자 명단 추출 → 별도 발송 → 리마인드"라는 후속 운영이 따라붙는다. 3주 프로그램이 오늘 끝나는데 그 운영을 며칠 더 끌 여력이 있는지가 관건이다.

**2. 완주 직후가 가장 협조적인 순간이다.** 설문을 다 채운 사람은 심리적으로 "이왕 하는 김에"에 가장 열려 있다. 며칠 뒤 별도 링크는 그 온기가 식은 뒤에 도착한다.

**3. 구글폼 섹션 분기로 B안 효과의 대부분을 낼 수 있다.** "보너스 미션에 참여하시겠어요?"라는 문항 하나로 분기하면, 참여 의사가 없는 사람은 곧바로 제출로 넘어간다. 폼은 하나지만 체감은 2단 분리와 같다.

### 그래도 B안이 나은 경우

**벤치마킹 데이터의 질이 개수보다 중요하다면 B안이다.** A안에서 "지금 가서 써보고 오세요"는 결국 그 자리에서 급하게 훑고 답하게 만든다. B안은 "이번 주 안에 편할 때"라고 말할 수 있어 실제로 써보고 답할 확률이 높다.

**보상을 걸 예산이 있다면 B안 응답률이 A안을 확실히 앞선다.** 이 집단은 미션-리워드에 반응한다는 것이 3주간 데이터로 증명됐다(7/20 4건 → 7/21 39건, 10배 진폭).

## 1. 공통 본체 (A안·B안 동일 · 17문항 · 약 8분)

> **소요 시간 산출** — 객관식 12개(×15초) + 그리드 1개 7행(×8초) + 척도 3개(×10초) + 필수 단답 2개(×40초) + 필수 장문 1개(×60초) = **약 7~8분.**
> 보너스 미션까지 하면 서비스 실사용 5분 + 문항 5분이 더해져 **총 17~18분**이 된다. A안 안내문에 "본 설문 10분"이라고만 쓰고 보너스를 별도 5분으로 명시하는 이유다.
>
> **더 줄여야 한다면 Q12(1순위 기능의 사용 상황)를 선택으로 내린다.** 40초가 줄고, 대신 기능 스펙을 쓸 때 맥락이 사라진다. Q13(자유 제안)은 절대 선택으로 내리지 않는다 — 이번 설문의 존재 이유다.
