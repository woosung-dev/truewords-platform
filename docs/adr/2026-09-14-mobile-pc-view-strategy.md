## 배경

`apps/web` 챗 화면은 본문·입력·footer가 모두 `mx-auto max-w-2xl`(672px)로 고정된 모바일 단일 컬럼이며, 데스크톱 breakpoint 분기가 사실상 없다(`md:`/`lg:`/`xl:` 0회). 1440px 모니터에서 중앙 672px만 쓰인다.

2026-09-14 PC 데스크톱 시안 4안(3-pane)을 제작한 뒤, 모바일(단일 컬럼 + 바텀시트)과 정보구조가 달라 **"뷰를 별도로 관리해야 하는가"** 라는 질문이 제기됐다. 전략 5안을 설계하고 3개 렌즈(유지보수·기술부채 / 실행 위험 / 제품 전략 정합)로 비교 판정했다.

## 조사에서 확인된 사실

1. **"모바일 우선"은 측정된 결론이 아니라 주어진 전제다.** `docs/research/2026-08-30-pwa-app-direction.md:14` 에서 이 문장은 `### 확인 사실` 절에 있고, 근거·대안 비교·기각 사유가 없다. 승인 결정 `DEC-PWA-009` 의 대립축은 **"네이티브 앱 vs 웹/PWA"** 였지 "모바일 vs PC"가 아니었다. PC 뷰를 기각한 결정은 레포 어디에도 없고, 폼팩터를 다룬 ADR도 0건이었다.
2. **PRD의 데스크톱 조항은 접근성 조항이다.** `REQ-PWA-014` 는 제목이 "접근성·반응형 품질"이고 본문 첫 문장이 "핵심 과업은 모바일 우선이며 WCAG 2.2 AA 수준으로…"다. `AC-PWA-014-01`("390px 모바일과 데스크톱에서 가로 스크롤 없이 핵심 플로우를 완료한다")은 **데스크톱 "지원"을 요구하지 "전용 정보구조"를 요구하지 않는다.**
3. **기기 분포 데이터가 0이고 소급 불가하다.** 서버가 User-Agent를 읽는 곳 0, 프론트 텔레메트리 0, DB 테이블 10개 전수에 device 컬럼 0. `research_sessions.client_fingerprint` 는 유일한 쓰기 지점이 하드코딩 `None`(`chat/pipeline/stages/session.py:62`)이라 한 번도 채워진 적이 없다.
4. **기기·화면 관련 사용자 피드백이 0건이다.** 체험단 33명(질문 518건 / 3주)의 자유서술 결함 지적 40여 종이 전부 콘텐츠 품질이었다. 그 체험단마저 98%가 선문대 신학과 학생이다.
5. **PC 시안의 핵심 기능은 프론트 문제가 아니다.** 시안 4안이 공통 채택한 P0-3(문장↔청크 각주 정렬)·P0-4(호버 프리뷰)는 `ChatSourcesEvent` 가 문장↔청크 매핑을 내려주지 않아 **RAG 응답 스키마 확장 + 렌더러 재작성**이 선행돼야 한다.
6. **안전망이 없다.** `apps/web/src/test/` 10개 파일 중 `(chat)/page.tsx` 를 렌더하는 것이 0개다.

## 결정

### `DEC-VIEW-001` — D→A 순차 전략을 채택한다

PC 전용 뷰를 지금 만들지 않는다. 계측을 먼저 붙이고, 데이터가 데스크톱 사용을 보이면 그때 **반응형 단일 뷰(A안)** 로 확장한다.

| 단계 | 내용 |
|---|---|
| 0 | 기기 계측 — `research_sessions.device_class` 파생 컬럼 + 집계 + admin 분포 카드 |
| 1 | 안전망 — `(chat)/page.tsx` 렌더 테스트 4경로 |
| 2 | 데스크톱 하한 — `AC-PWA-014-01` 충족. 정보구조 불변 |
| 3 | 부채 정리 — `useChatSession()` 추출, 중복·dead code 제거 |
| 4 | 4~8주 뒤 계측 데이터로 재판단 (<10% D 유지 / 10~30% A 부분 / >30% A 전체 + 백엔드 확장 검토) |

**기각한 대안**

- **B 공유 훅 + 뷰 2벌 분리** (3렌즈 합 6/15) — 뷰 2벌을 영구 확정하면서 행동 동일성 강제 장치가 0이다. 드리프트를 감지할 신호(텔레메트리·기기 피드백·2인 이상 리뷰)가 이 프로젝트에 구조적으로 부재하다
- **C 라우트/엔트리 분리** (3/15) — 위험이 "레이아웃 파손"이 아니라 "진입점 파손" 급이고, 미착수 M5(PWA)의 `manifest.start_url`·서비스워커 precache에 되돌릴 수 없는 선제 제약을 건다
- **E 점진적 강화** (10/15) — A안의 하위 집합에 가깝고 되돌리기 이점이 A보다 작다

### `DEC-VIEW-002` — PC 전용 시안 4안을 폐기한다

`docs/design/2026-09-pc-chat/` 의 HTML 9개(챗 4안 × 3상태 + 소개 4안 + 비교 보드, 약 467KB)를 삭제한다. 구조 요약(`README.md`)만 [archive](../archive/design-2026-09-pc-chat/README.md)로 보존한다.

**사유:** 4안 전부 3-pane 정보구조 재설계인데, 채택된 A안은 "모바일 골격을 유지하고 breakpoint로 분기한다"이므로 전제가 정면으로 어긋난다. 또한 §5(P0-3/P0-4 백엔드 선행)에 따라 설령 3-pane으로 가더라도 시안을 그대로 쓸 수 없다.

## 결과

- **긍정** — 뷰가 1벌로 유지되어 드리프트가 구조적으로 차단된다. 단계 1·3은 PC 결정과 무관하게 순이익이다(1217줄 단일 컴포넌트·훅 0개는 그 자체로 부채). 배포 구조 변경이 없다
- **비용** — 데스크톱 가로 폭 낭비가 최소 4~8주 더 지속된다. 단계 2가 하한만 충족하므로 시각적 개선은 제한적이다
- **되돌리기** — 단계 4에서 데이터가 3-pane을 지지하면 시안을 새로 뽑아야 한다(폐기했으므로). 다만 그때는 확정된 기기 데이터와 확정된 `DEC-PWA-017` 정보구조 위에서 뽑는 것이 맞다
