## 1. 제품 정의

### 1.1 해결할 문제

가정연합 현 구성원과 그 가정이 말씀을 찾고 이해하려 할 때 다음 문제가 반복된다.

1. 자료가 여러 출판물·사이트·판본에 흩어져 있어 정확한 발화자·날짜·판본·원문 맥락을 확인하기 어렵다.
2. 고유 용어와 시대별 표현이 어려워 짧은 검색만으로는 의미와 관련 원문을 연결하기 어렵다.
3. 생성형 AI의 설명과 공식 원문이 섞이면 사용자가 AI 요약을 공식 해석으로 오인할 수 있다.
4. 오늘 읽을 분량을 고르고 가족의 생활 실천으로 연결하는 일상 루프가 약하다.
5. 질문·메모·가족 맥락은 민감하지만 저장·삭제·알림 노출 범위를 사용자가 통제하기 어렵다.

### 1.2 한 문장 가치제안

> **AI가 신앙의 답을 대신하는 앱이 아니라, 권리가 확인된 말씀의 정확한 출처와 맥락으로 사용자를 되돌려 보내고 오늘의 가족 실천까지 연결하는 모바일 우선 말씀 PWA.**

### 1.3 운영 및 독립 베타 표시 원칙

- 대상 조직은 FFWPU다.
- 공식 승인 전까지 독립 운영·비공식 제한 베타로만 제공한다.
- 공식 로고, 공식 앱이라는 주장, 공식 기관과의 제휴를 암시하는 표현을 사용하지 않는다.
- 첫 진입, 로그인, 정보 화면, 공유 화면에 독립 베타임을 일관되게 표시한다.
- 승인되지 않은 콘텐츠는 원문·검색색인·임베딩·AI 근거·오프라인·푸시 인용에 사용하지 않는다.
- `[확인 필요]` 법적 운영 주체와 공식 승인 절차가 확정되기 전에는 외부 공개 모집과 S12 베타 배포를 진행하지 않는다.

독립 베타 기본 고지문:

> 이 서비스는 FFWPU 공식 앱이 아닌 독립 운영 제한 베타입니다. AI 설명은 공식 원문이나 공식 해설이 아니며, 각 답변의 출처와 검수 상태를 확인해 주세요.

### 1.4 대상 사용자와 비사용자

| 구분 | 사용자 | 핵심 필요 |

| 후속 | 청년·2세대·다문화 가정 | 쉬운 맥락 설명, 판본·번역 차이, 원문 연결 |

- 권리 미확인 전체 615권을 내려받거나 대량 수집하려는 사용자
- `[확인 필요]` 보호자 동의·연령 정책이 필요한 아동 단독 사용자

## 2. 핵심 사용자 경험

### 2.1 오늘의 말씀

1. 사용자는 권리가 확인된 오늘의 말씀과 예상 읽기 시간을 본다.
2. 본문에서 발화자·날짜·출판물·판본·공식성·검수 상태를 연다.
3. 낯선 용어와 앞뒤 맥락을 확인한다.
4. 한 줄 성찰·실천을 비공개로 저장하거나 저장 없이 완료한다.
5. 첫 가치 경험 뒤에만 설치 또는 알림을 선택적으로 제안받는다.

### 2.2 통합 검색

1. 사용자는 제목·화자·연도·주제·정확한 문구·자연어 중 아는 정보만 입력한다.
2. 결과에서 일치 이유, 원문 일부, 출처, 공식성, 판본을 비교한다.
3. 필터가 과도해 0건이면 어떤 조건을 풀면 되는지 확인한다.
4. 결과 상세에서 전체 허용 원문, 관련 용어, 관련 말씀으로 이동한다.

### 2.3 출처 있는 질문

1. 사용자는 질문을 입력하고 저장 또는 무기억 모드를 확인한다.
2. 시스템은 권리·공식성 필터를 통과한 근거만 검색한다.
3. 답변은 AI 요약, 핵심 인용, 출처 메타데이터를 분리해 표시한다.
4. 사용자는 각 주장에 연결된 원문 문단을 연다.
5. 판본이 충돌하거나 근거가 부족하면 시스템은 합성 답변을 중단한다.

### 2.4 원문·용어 탐색

1. 사용자는 인용 또는 검색 결과에서 원문 상세를 연다.
2. 공식 원문, 공식 해설, AI 설명, 사용자 메모의 권위 층을 구분한다.
3. 용어 정의에서 사용 시대·출처·관련 판본과 원문으로 이동한다.
4. 판본·번역 차이는 하나로 합치지 않고 나란히 비교한다.

### 2.5 내 서재와 설치·알림

1. 로그인 사용자는 북마크·최근 읽기·개인 메모를 비공개로 관리한다.
2. 사용자는 기록별 저장 여부와 질문 무기억 모드를 선택한다.
3. PWA 설치와 알림은 첫 읽기 또는 저장 완료 뒤에만 제안한다.
4. 알림 기본 문구는 중립형이며 시간대·희망 시각·조용한 시간을 사용자가 설정한다.
5. 알림 권한을 거부해도 앱 내 알림함과 모든 핵심 읽기 기능을 사용할 수 있다.

## 3. 요구사항

### 3.1 우선순위

- `P0`: 제한 베타 진입을 막는 필수 요구사항
- `P1`: MVP 범위이며 G5에서 명시적으로 제외하지 않는 한 베타 전에 완료
- `P2`: 베타 데이터로 우선순위를 다시 정할 후속 요구사항

### `REQ-PWA-001` 독립 베타 정체성 (`P0`)

공식 승인 전 모든 사용자 접점은 독립 운영·비공식 제한 베타임을 명확히 표시해야 한다.

- `AC-PWA-001-01`: 첫 진입·로그인·정보·공유 화면에서 “FFWPU 공식 앱이 아님”과 AI 설명의 비공식성을 확인할 수 있다.
- `AC-PWA-001-02`: 공식 로고·공식 제휴 표현이 없는지 릴리스 체크리스트와 화면 문자열 검사에서 확인한다.
- `AC-PWA-001-03`: 고지문 확인 전 사용자가 공식 앱으로 오인할 수 있는 설치 이름이나 알림 발신자명을 사용하지 않는다.

### `REQ-PWA-002` 오늘의 말씀 (`P0`)

사용자는 권리가 확인된 오늘의 말씀을 3분 내 읽고 출처·용어·한 줄 실천으로 이동할 수 있어야 한다.

- `AC-PWA-002-01`: 오늘 콘텐츠에는 예상 읽기 시간, 발화자, 날짜, 저작물, 판본, 공식성, 검수 상태가 표시된다.
- `AC-PWA-002-02`: 사용자는 로그인하지 않아도 공개 권리가 허용된 오늘 콘텐츠를 읽을 수 있다.
- `AC-PWA-002-03`: 한 줄 실천은 저장 없이 완료하거나 로그인 후 비공개 저장할 수 있다.
- `AC-PWA-002-04`: 오늘 콘텐츠가 없거나 철회됐으면 대체 콘텐츠를 임의 생성하지 않고 상태와 다음 탐색 행동을 표시한다.

### `REQ-PWA-003` 통합 검색 (`P0`)

사용자는 정확한 문구와 자연어를 하나의 진입점에서 검색하고 출처 메타데이터로 결과를 좁힐 수 있어야 한다.

- `AC-PWA-003-01`: 제목·화자·연도·주제·정확 문구·자연어 검색을 지원하고 적용된 필터를 화면에서 확인·해제할 수 있다.
- `AC-PWA-003-02`: 각 결과는 일치 문맥, 출처, 판본, 공식성, 검수·철회 상태를 표시한다.
- `AC-PWA-003-03`: 0건이면 빈 화면 대신 철자·필터 완화·관련 용어 제안을 제공하며 존재하지 않는 원문을 생성하지 않는다.
- `AC-PWA-003-04`: 권리 원장이 허용하지 않은 콘텐츠는 결과·미리보기·검색 제안에 노출되지 않는다.

### `REQ-PWA-004` 출처 있는 질문 (`P0`)

AI 답변은 승인된 근거에 제한되고 모든 핵심 주장과 인용 문단을 연결해야 한다.

- `AC-PWA-004-01`: 답변의 핵심 주장마다 하나 이상의 문단 단위 출처 링크가 있으며 링크는 실제 근거 문단을 연다.
- `AC-PWA-004-02`: AI 요약과 공식 원문은 라벨·영역·스크린리더 이름으로 구분된다.
- `AC-PWA-004-03`: 검색 또는 생성 실패 시 추정 답변을 표시하지 않고 재시도와 원문 검색 행동을 제공한다.
- `AC-PWA-004-04`: 의료·법률·위기·교리 판정 요청은 제품 권한의 한계를 알리고 적절한 공식·전문 경로를 안내한다.

### `REQ-PWA-005` 원문과 출처 상세 (`P0`)

사용자는 인용의 발화·출판·판본 맥락과 권위 층을 감사 가능한 형태로 확인해야 한다.

- `AC-PWA-005-01`: 상세 화면은 발화자, 발화일·장소(확인된 경우), 저작물, 판본·언어, 위치 식별자, 공식성, 검수일을 표시한다.
- `AC-PWA-005-02`: 메타데이터가 확인되지 않은 필드는 추정값으로 채우지 않고 “확인되지 않음”으로 표시한다.
- `AC-PWA-005-03`: 공유 링크는 현재 권리·철회 상태를 서버에서 다시 확인하고 철회 시 원문 대신 철회 안내를 표시한다.

### `REQ-PWA-006` 용어 탐색 (`P0`)

고유 용어는 말씀 본문과 분리된 사전 근거로 설명하고 관련 원문과 연결해야 한다.

- `AC-PWA-006-01`: 용어 정의에는 정의 출처, 공식성, 적용 시대·판본, 검수 상태가 표시된다.
- `AC-PWA-006-02`: 용어 사전 결과가 말씀 검색 결과를 대체하거나 원문 인용으로 표시되지 않는다.
- `AC-PWA-006-03`: 정의가 충돌하면 복수 정의를 나란히 표시하고 단일 공식 의미로 합성하지 않는다.

### `REQ-PWA-007` 내 서재 (`P1`)

로그인 사용자는 북마크·최근 읽기·개인 메모를 기본 비공개로 저장·삭제할 수 있어야 한다.

- `AC-PWA-007-01`: 저장 항목은 본인 계정에서만 조회되고 관리자용 `AdminUser` 권한·세션과 분리된다.
- `AC-PWA-007-02`: 사용자는 항목별 삭제와 계정 전체 삭제를 실행하고 처리 상태를 확인할 수 있다.
- `AC-PWA-007-03`: 철회 콘텐츠를 저장한 경우 개인 메모는 보존 여부를 사용자가 선택할 수 있지만 철회 원문은 재노출되지 않는다.
- `AC-PWA-007-04`: 로그아웃·세션 만료·권한 오류에서 개인 기록을 다른 사용자에게 노출하지 않는다.

### `REQ-PWA-008` 일반 사용자 인증·동의·무기억 (`P0`)

소비자 인증과 개인정보 모델은 관리자 인증과 분리하고 최소 수집·명시적 저장을 적용해야 한다.

- `AC-PWA-008-01`: 일반 사용자와 `AdminUser`는 별도 엔티티·세션·쿠키 범위·권한 검사를 사용한다.
- `AC-PWA-008-02`: 공개 권리가 허용된 오늘·검색·원문 읽기는 비로그인으로 가능하고, 서재·메모·푸시 설정은 로그인이 필요하다.
- `AC-PWA-008-03`: `[제안]` 질문은 기본 무기억이며 사용자가 저장을 선택한 경우에만 질문·답변 원문을 계정에 보관한다.
- `AC-PWA-008-04`: 동의 거부·철회가 핵심 공개 읽기 기능을 막지 않으며 필요한 기능만 정확히 잠근다.

### `REQ-PWA-009` 설치와 제한 오프라인 (`P1`)

PWA는 설치 가능해야 하며 권리가 허용된 비민감 콘텐츠만 제한적으로 오프라인 제공해야 한다.

- `AC-PWA-009-01`: 지원 브라우저에서 manifest 이름·아이콘·시작 URL·standalone 표시가 검증되고, 미지원 환경에는 일반 웹 이용 경로를 제공한다.
- `AC-PWA-009-02`: 첫 가치 경험 전에 설치 프롬프트를 강제하지 않는다.
- `AC-PWA-009-03`: 앱 셸과 명시적으로 허용된 공개 본문만 캐시하며 질문·답변·메모·가족 정보·인증 토큰은 Service Worker 캐시에 저장하지 않는다.
- `AC-PWA-009-04`: 오프라인에서는 RAG 질문과 최신 권리 확인이 불가능함을 표시하고 마지막 동기화 시각을 보여준다.

### `REQ-PWA-010` 중립형 알림과 알림함 (`P1`)

알림은 사용자의 명시적 선택 뒤 중립형 문구로 제공하고 앱 내 알림함을 최종 전달 수단으로 사용해야 한다.

- `AC-PWA-010-01`: 첫 읽기 또는 저장 완료 뒤 사용자가 “알림 켜기”를 탭한 직후에만 브라우저 권한을 요청한다.
- `AC-PWA-010-02`: 기본 잠금 화면 문구에는 질문·답변·기도·가족 정보·말씀 전문·신앙 맥락이 포함되지 않는다.
- `AC-PWA-010-03`: 권한 거부·미지원·전달 실패에서도 알림함과 설정 경로를 제공하며 권한을 반복 요청하지 않는다.
- `AC-PWA-010-04`: 사용자는 시간대·희망 시각·조용한 시간·문구 수준을 바꾸고 브라우저 구독과 서버 예약을 함께 해지할 수 있다.

### `REQ-PWA-011` 콘텐츠 권리 원장과 철회 (`P0`)

모든 콘텐츠는 기능별 권리와 공식성·검수·철회 상태를 가진 원장 레코드 없이는 제품에 진입할 수 없다.

- `AC-PWA-011-01`: 원장에 권리자, 근거 문서, 유효 기간, 지역, 판본, O1~O5/R, 검수자, 철회 책임자, 기능별 허용값을 기록한다.
- `AC-PWA-011-02`: 본문 전재·검색·임베딩·AI 요약·오프라인·푸시 인용 각각이 `allowed`인 경우에만 해당 파이프라인이 동작한다.
- `AC-PWA-011-03`: 철회 시 서버 원문·검색색인·임베딩·캐시·AI 요약·공유 링크를 함께 차단하고 감사 로그를 남긴다.
- `AC-PWA-011-04`: 오프라인 사본은 다음 온라인 동기화에서 삭제·재제공 차단하며 즉시 원격 삭제를 보장하지 않는다는 한계를 표시한다.

### `REQ-PWA-012` 권위 층·판본 충돌·근거 부족 중단 (`P0`)

제품은 공식성 등급과 판본 충돌을 숨기지 않고 근거가 부족하면 답변을 중단해야 한다.

- `AC-PWA-012-01`: O1~O5/R 등급과 “공식 원문·공식 해설·AI 요약·사용자 메모” 유형을 데이터와 화면 모두에서 별도 필드로 유지한다.
- `AC-PWA-012-02`: 핵심 근거가 R뿐이면 기본 AI 답변에서 제외하고 참고 자료임을 별도로 표시한다.
- `AC-PWA-012-03`: 판본·번역·시대별 진술이 충돌하면 차이를 나란히 보여주고 하나의 결론으로 조용히 합치지 않는다.
- `AC-PWA-012-04`: 근거 수·관련도·인용 검증 기준을 충족하지 못하면 “확인할 수 없음”으로 끝내고 원문 검색 또는 공식 문의 경로를 제공한다.

### `REQ-PWA-013` 오류·빈 결과·오프라인·권한 상태 (`P0`)

핵심 플로우는 실패 원인과 안전한 다음 행동을 구분해 제공해야 한다.

- `AC-PWA-013-01`: 네트워크 실패는 입력을 잃지 않고 재시도할 수 있으며 중복 저장·중복 질문 전송을 방지한다.
- `AC-PWA-013-02`: 빈 결과는 “오류”와 구분하고 필터 해제·관련 용어·공식 문의 행동을 제공한다.
- `AC-PWA-013-03`: 오프라인, 인증 만료, 접근 권한 없음, 알림 권한 거부, 콘텐츠 철회 상태를 서로 다른 메시지와 행동으로 표시한다.
- `AC-PWA-013-04`: 서버 내부 정보·토큰·원문 권리 정보가 오류 메시지나 로그에 노출되지 않는다.

### `REQ-PWA-014` 접근성·반응형 품질 (`P0`)

핵심 과업은 모바일 우선이며 WCAG 2.2 AA 수준으로 키보드·스크린리더·큰 글씨에서 수행 가능해야 한다.

- `AC-PWA-014-01`: 390px 모바일과 데스크톱에서 가로 스크롤 없이 핵심 플로우를 완료한다.
- `AC-PWA-014-02`: 텍스트 200% 확대, 키보드, 명확한 포커스, 스크린리더 이름, reduced-motion에서 정보 손실이 없다.
- `AC-PWA-014-03`: 공식성·권위·오류 상태를 색상이나 아이콘 하나만으로 구분하지 않는다.

### `REQ-PWA-015` 개인정보 보호형 측정 (`P0`)

KPI 측정은 원문 질문·메모·가족 정보 없이 과업 완료와 안전 지표만 수집해야 한다.

- `AC-PWA-015-01`: 분석 이벤트에 원문 질문, 답변, 메모, 검색어, 푸시 endpoint·키를 넣지 않는다.
- `AC-PWA-015-02`: 이벤트 사전에 목적·속성·보존 기간·접근 역할을 기록하고 동의 범위를 벗어난 이벤트를 차단한다.
- `AC-PWA-015-03`: 계정 삭제 시 사용자 식별 이벤트 연결을 끊고 법적 보존 의무가 없는 원본 이벤트를 정책 기한 내 삭제한다.

### 3.2 실패 상태 매트릭스

| 상태 | 사용자 표시 | 허용 행동 | 금지 행동 |
|---|---|---|---|

## 4. 신뢰·콘텐츠·개인정보

### 4.1 O1~O5/R 공식성

| 등급 | 의미 | 기본 검색·AI 정책 |
|---|---|---|
| O1 | 승인된 정본·공식 판본 | 권리 허용 기능에서 우선 사용 |
| O2 | 공식 출처가 게시한 말씀·메시지 | 게시 주체·시점과 함께 사용 |
| O3 | 공식 교육·해설 | 원문이 아닌 해설 유형을 표시하고 사용 |
| O4 | 역사자료·잡지·회고 | 시대·작성자·한계를 표시하고 보조 사용 |
| O5 | 지역·기관 콘텐츠 | 게시 주체와 적용 범위를 표시하고 제한 사용 |
| R | 참고·미검증 자료 | 기본 AI 답변에서 제외 |

공식성은 권리 허가를 대신하지 않는다. O1이어도 기능별 권리가 `allowed`가 아니면 사용할 수 없다.

### 4.2 콘텐츠 권리 원장 최소 필드

| 영역 | 필수 필드 |
|---|---|
| 식별 | `content_id`, 제목, 판본, 언어, 원본 위치 식별자 |
| 출처 | 발화자·저자, 발화·발행일, 장소, 게시 주체 |
| 권리 | 권리자, 증빙 URI, 유효 기간, 지역, 이용 조건 |
| 기능별 권리 | 본문 전재, 검색, 임베딩, AI 요약, 오프라인, 푸시 인용 |
| 신뢰 | O1~O5/R, 콘텐츠 유형, 검수자, 검수일 |
| 수명주기 | 상태, 철회 사유, 효력 시각, 철회 책임자, 감사 로그 |

기능별 권리는 `allowed`, `denied`, `pending`, `expired`, `withdrawn` 중 하나로 기록한다. `allowed` 외 상태는 기본 거부한다.

### 4.3 AI 요약과 공식 원문의 분리

- 공식 원문은 수정하지 않고 판본과 위치 식별자를 유지한다.
- AI 요약에는 “AI 설명”을 명시하고 핵심 주장별 원문 링크를 붙인다.
- 공식 해설은 AI 요약과 별도 유형으로 표시한다.
- 사용자 메모는 본인만 보는 비공식 기록으로 표시한다.
- 인용문을 AI가 의역했으면 인용부호를 사용하지 않고 요약으로 표시한다.

### 4.4 판본 충돌과 근거 부족

- 충돌 판본은 최신성만으로 자동 승자 판본을 정하지 않는다.
- 공식성·검수·권리 상태와 차이 나는 문구를 함께 보여준다.
- 관련 근거가 없는 경우 일반 상식이나 모델 사전 지식으로 종교적 결론을 보충하지 않는다.
- 안전·의료·법률·위기 상황은 공식 말씀 검색과 별개로 적절한 전문 지원 경로를 안내한다.

### 4.5 개인정보 보존·삭제·무기억

| 데이터 | 기본 정책 | `[제안]` 보존·삭제 기준 |
|---|---|---|
| 무기억 질문·답변 | 계정 기록에 저장하지 않음 | 응답 완료 뒤 원문 비보관, 보안 로그는 원문 없이 30일 |
| 저장 질문·답변 | 명시적 저장 시만 비공개 보관 | 사용자 삭제 즉시 숨김, 운영 DB 24시간 내 삭제, 백업 30일 내 만료 |
| 북마크·메모·한 줄 실천 | 기본 비공개 | 사용자 삭제 또는 계정 삭제까지 |
| 최근 읽기 | 기능별 끄기 제공 | 90일 후 자동 만료 |
| 계정·동의 이력 | 최소 계정 식별·동의 버전 | 계정 삭제 시 24시간 내 비식별·삭제, 법정 보존분 별도 격리 |
| 분석 이벤트 | 원문·민감 내용 금지 | 가명 이벤트 90일 후 집계·원본 삭제 |
| Push 구독 | endpoint·키 암호화 | 해지 또는 404/410 확인 즉시 비활성, 24시간 내 삭제 |

- `[확인 필요]` 실제 보존 기간은 법적 운영 주체·적용 법률·개인정보처리방침 확정 후 G3에서 승인한다.
- 관리자 계정은 일반 사용자 기록을 기본 열람할 수 없다. 운영상 열람이 필요하면 별도 목적·권한·감사 로그·사용자 고지가 필요하다.
- JWT, Push payload, Service Worker 캐시, 분석 이벤트에 질문·메모·가족 정보를 복사하지 않는다.
- 계정 삭제는 PostgreSQL, 검색·캐시 파생 데이터, Push 구독, 향후 예약을 함께 처리한다.

## 5. 제품 의사결정

### 5.1 MVP와 비범위

| MVP | 비범위 |
|---|---|
| 모바일 우선 웹/PWA | 네이티브 앱 |
| 권리 승인 소규모 정본의 오늘·검색·질문·원문·용어 | 권리 확인 전 615권 전체 공개 |
| 비공개 서재·메모·무기억 | 공개 커뮤니티·댓글·DM·실시간 그룹 피드 |
| 일반 사용자 인증·동의·삭제 | AdminUser 재사용, 출석·GPS·전도·신앙 점수 |
| 제한 오프라인·중립형 알림·알림함 | 완전 오프라인 RAG, 민감 정보 Push |
| 출처·공식성·판본·검수·철회 표시 | AI를 공식 해설·목회자·교리 판단으로 표시 |
| 비용·사용 빈도 측정 | 결제·광고·구독 가격 확정 |

비범위 기능은 MVP 성공 기준에 포함하지 않으며, 비범위가 없어도 핵심 플로우가 완결되도록 설계한다.

### 5.2 KPI와 측정 이벤트

제한 베타의 북극성 지표는 **주간 출처 확인 가치 도달률**이다. 단순 방문이나 AI 질문 수가 아니라 사용자가 원문 출처까지 확인한 비율을 본다.

#### 핵심 KPI

| KPI | 계산식·데이터 원천 | 의사결정 | `[제안]` 목표 |
|---|---|---|---|

| 이벤트 | 발생 조건 | 허용 속성 |
|---|---|---|
| `session_started` | 새 제품 세션 시작 | `surface`, 가명 `actor_id` |

이벤트 공통 속성은 `event_id`, 가명 `actor_id`, `occurred_at`, `surface`, `content_id`, `officiality`, `result_state`로 제한한다. 검색어·질문·답변·메모 원문은 수집하지 않는다.

새 제품이라 내부 기준선이 없다. 따라서 목표는 외부 벤치마크가 아닌 `[제안]` 초기 Go/No-Go 기준이며 신뢰도는 낮다. S2는 `[제안]` 5~8명으로 방향성을 보고, 비율과 원시 성공 인원을 함께 기록한다. 첫 제한 베타 2주 뒤 실제 분포와 코호트 크기로 목표를 재승인한다.

### 6.2 S2 사용자 과업

1. 오늘의 말씀을 3분 안에 읽고 출처를 확인한 뒤 저장 또는 저장 안 함을 선택한다.
2. 기억나는 문구나 주제로 통합 검색하고 올바른 판본의 원문을 연다.
3. 질문 후 AI 요약과 공식 원문을 구분하고 인용 문단·화자·날짜·공식성·검수 상태를 확인한다.
4. 낯선 용어에서 복수 정의 또는 관련 원문으로 이동한다.
