## 0. 이 문서의 경계

| 담는 것 | 담지 않는 것 |
|---|---|
| A 안의 색·타이포·간격·모서리·그림자·상태 토큰 | 다크 팔레트 (베타 라이트 고정, `DEC-PWA-017`) |
| 컴포넌트 10종의 구조·치수·상태·접근성 | 데스크톱 전용 정보구조·화면 (`REQ-PWA-014`는 반응형 조항이지 데스크톱 IA 요구가 아니다) |
| 컴포넌트별 대비 실측값과 WCAG 2.2 AA 판정 | 컴포넌트 코드·프레임워크 선택·파일 배치 (S4 구현 계획) |
| 390 / 768 / 1280px 반응형 규칙과 16화면 대응표 | API·도메인 모델·상태 관리 (S4) |

경계 규칙 세 가지.

1. **[`UI-WEB-001`](ui-ux.md)은 건드리지 않는다.** 현재 `apps/web`의 시연 화면(`/`, `/history`, `/about`, `/login`, `/design-system`)은 별개 제품의 보존 기준이다. 훈독은 같은 앱 안에 들어가지만 이 문서가 화면 규칙을 따로 소유한다.
2. **공통 UI 패키지를 만들지 않는다.** [`APP-UI-001`](../../plans/active/2026-09-05-app-owned-ui.md)이 UI·테마를 앱별 소유로 확정했다. 토큰 값이 기존 web과 같아 보여도 공용 패키지로 승격하지 않는다.
3. **뷰를 두 벌 만들지 않는다.** 데스크톱은 같은 컴포넌트의 반응형 규칙으로 처리한다(§4). 모바일 뷰와 데스크톱 뷰를 분리하면 한쪽만 고쳐지는 드리프트가 생기고, 이 저장소에는 그 드리프트를 감지할 텔레메트리가 없다.

시안 HTML과 스크린샷은 5번째 탭을 **"나의 뜰"**로 표기한다. 2026-09-10 산출물이기 때문이며, 확정 명칭은 **"나의 정원"**(`DEC-PWA-015`)이다. 구현은 확정 명칭을 따른다.

## 1. 토큰

### 1.1 색

라이트 단일 팔레트. 액센트는 감귤 1색이며, 초록은 **완료 시맨틱 전용**이라 액센트가 아니다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--paper` | `#fbfaf8` | 앱 바탕. 웜 오프화이트 (크림·베이지 아님) |
| `--surface` | `#ffffff` | 카드·시트 위 표면·탭바·입력 |
| `--surface-2` | `#f1efea` | 보조 표면. 미션 아이콘 칩, 진행 바 트랙, 정보 박스, 비활성 |
| `--ink` | `#23211f` | 본문·제목. 순흑 아님 |
| `--ink-2` | `#5a5652` | 보조 본문, 폼 라벨, 리더 바 라벨 |
| `--ink-3` | `#6f6a65` | 메타 정보, 플레이스홀더, 컨트롤 경계선 |

**시안의 `--bg #f4f2ee`는 토큰이 아니다.** 프로토타입에서 폰 프레임 뒤를 채우는 스테이지 배경이며 앱에는 존재하지 않는다. 데스크톱에서 본문 바깥을 채우는 색은 `--paper`다.

**`#d4562e`는 폐기값이다.** 흰 글자 대비 4.1:1로 WCAG 2.2 AA(4.5:1) 미달이라 시안 제작 중 `#c24721`(4.98:1)로 교체했다. 문서·코드 어디에서 발견되든 오류로 취급하고 `--accent`로 고친다.

색 사용 규칙 네 가지.

- 액센트는 **한 화면에 목적 하나**. 활성 탭·주 버튼·진행 바·연속일 숫자가 동시에 액센트일 수 있으나, 새로운 의미에 액센트를 더 배정하지 않는다.
- 초록(`--ok*`)은 **완료**와 **정본 등급(O1·O2)** 두 곳에만 쓴다 (2026-09-16 `DES-PWA-003-Q1` 확정). 성공 토스트·유효성 통과·오류 없음 표시에는 쓰지 않는다.
- 상태를 색으로만 알리지 않는다(§3.3). 모든 색 상태에는 아이콘·텍스트·형태 중 하나가 동반된다.
- 그라데이션은 사진 위 veil 한 곳뿐이다. 버튼·카드·배경에 그라데이션을 쓰지 않는다.

### 1.2 타이포 스케일

서체는 **Pretendard 단일**이다. 굵기만으로 위계를 만들며 세리프를 섞지 않는다(`DEC-PWA-017`이 B의 세리프 인용을 미채택). 시안 CSS에 `.serif-quote` 규칙이 남아 있으나 A의 마크업에서 한 번도 쓰이지 않는 죽은 선언이므로 옮기지 않는다.

font-family: "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont,

**아이콘 크기**는 텍스트 스케일과 별개다. 14 (인라인 caret) · 20 (리스트 안) · 22 (리더 바·아이콘 버튼) · 24 (탭바·미션 아이콘) · 26 (빈 상태) · 28 (중앙 탭 버블) 여섯 단계만 쓴다.

**rem 환산.** 위 값은 루트 16px 기준 px 표기다. 구현에서는 `rem`으로 옮겨 브라우저 글자 크기 설정과 200% 확대가 동작하게 한다(§3.4). 소수 px(12.5·13.5·14.5·16.5)은 시안의 실제 값이므로 정수로 반올림하지 않는다 — 반올림하면 카드 안 세 줄의 위계가 무너진다.

### 1.4 모서리·테두리·그림자

**모서리는 16px 단일 체계다.** 버튼·카드·입력·시트 콘텐츠가 같은 값을 쓴다. 파생값은 아래 네 개뿐이며 새 반지름을 만들지 않는다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `--r` | 16px | 카드, 버튼, 히어로 사진, AI 박스, 노트 박스, 오디오 바 |
| `--r-sm` | 12px | 입력, 칩 버튼, 아이콘 버튼, 미션 아이콘(14px→12px로 통합), 토스트 |
| `--r-xs` | 8px | 배지, 용어 칩 |
| `--r-sheet` | 28px | 바텀 시트 상단 두 모서리 |
| `--r-full` | 50% / 999px | 원형(체크·요일·아바타·중앙 버블)과 FAB pill |

시안의 미션 아이콘 칩은 14px, 입력·칩은 12px로 갈렸다. 12px으로 통일한다 — 1px 차이는 화면에서 구분되지 않으면서 구현에 단계를 하나 더 만든다.

테두리.

| 용도 | 값 | 이유 |
|---|---|---|
| 카드·구분선·그리드 | `1px solid --line` | 장식 경계. 대비 요구 없음 |
| 상태를 경계로만 알리는 컨트롤 (체크·라디오·토글 off·입력) | `1.5~2px solid --ink-3` | WCAG 1.4.11 비텍스트 3:1 (§6-3) |
| 공식 원문 인용 왼쪽 선 | `4px solid --ink` | 권위 층 형태 구분 |
| 내 메모 | `1.5px dashed --line` | 권위 층 형태 구분 |
| 세그먼트 활성 밑줄 | `2px solid --accent` | |

그림자는 세 단계다.

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `--shadow-hairline` | `0 1px 0 rgba(0,0,0,0.02)` | 카드 기본 |
| `--shadow-1` | `0 1px 2px rgba(0,0,0,0.06)` | pill 세그먼트의 활성 썸 |
| `--shadow-2` | `0 10px 30px rgba(87,62,40,0.10)` | FAB, 중앙 탭 버블, 데스크톱 중앙 모달 |

그림자 색은 검정이 아니라 웜 브라운(`87,62,40`)이다. 웜 뉴트럴 바탕에서 회색 그림자가 차갑게 뜨는 것을 막는다.

### 1.5 상태

시안은 `:active`와 입력 `:focus`만 정의했다. 나머지는 이 문서에서 정의한다 — 데스크톱이 범위에 들어오면서 hover가 필요해지고, 로그인·전송·스트리밍이 있는 제품에는 disabled·loading이 필요하다.

| 상태 | 규칙 | 대비 |
|---|---|---|
| **hover** (`@media (hover: hover)`에서만) | 채움 버튼: 배경을 `--accent-strong`(`#a03a1a`)으로. 연한 버튼·리스트 항목·칩: 배경을 `--surface-2`로. 카드: `--shadow-hairline` → `--shadow-1`. 색 변화 외 이동·확대 없음 | 흰 글자 / `#a03a1a` = **6.74:1** |
| **pressed** (`:active`) | 버튼 `transform: scale(0.985)`, 아이콘 버튼 `scale(0.96)`. 120ms ease | — |
| **focus-visible** | `outline: 2px solid --accent; outline-offset: 2px`. 모든 상호작용 요소에 적용하며 `outline: none` 금지. 액센트 채움 버튼 위에서는 대비가 부족하므로 `outline-color: --ink`로 바꾼다 | 액센트/`--paper` **4.77:1**, 잉크/액센트 **3.22:1** (둘 다 비텍스트 3:1 통과) |
| **selected** | 배경 `--accent-soft` + 글자·아이콘 `--accent-strong` + 테두리 `1px --accent`. 색만이 아니라 테두리가 함께 바뀐다 | `#a03a1a` / `#fbe9e1` = **5.73:1** |
| **completed** | 배경 `--ok-soft` + 글자 `--ok-strong` + **체크 아이콘 동반**. 아이콘 없이 초록만 쓰지 않는다 | `#26633f` / `#e4f1e8` = **6.14:1** |
| **disabled** | 배경 `--surface-2`, 글자 `--ink-3`, `cursor: not-allowed`, `aria-disabled="true"`. `opacity`로 흐리게 만들지 않는다(겹친 배경에 따라 대비가 예측 불가) | `--ink-3` / `--surface-2` = **4.66:1** (WCAG는 비활성 요소를 면제하지만 통과시킨다) |
| **loading (버튼)** | 라벨을 유지한 채 왼쪽에 16px 스피너. 버튼 폭을 고정해 레이아웃이 튀지 않게 한다. `aria-busy="true"`, 중복 제출 차단 | — |
| **loading (목록·카드)** | `--surface-2` 스켈레톤 블록. shimmer는 `prefers-reduced-motion`에서 정지하고 정적 회색으로 남는다 | — |
| **loading (AI 답변)** | 토큰 스트리밍 + "답변을 찾는 중" 상태 줄 + **중단 버튼**. 근거 말씀 카드는 스트리밍이 끝난 뒤 한 번에 나타난다(부분 인용이 확정 인용처럼 보이면 안 된다) | — |
| **empty** | 아이콘 26px `--ink-3` + 제목 `body-lg` + 설명 `meta-sm` + 다음 행동 버튼. 빈 결과에 가짜 대체 결과를 만들지 않는다 (`REQ-PWA-013`) | — |
| **error** | 카드 안 `--surface-2` 박스 + 원인 문장 + 재시도 버튼. 입력값을 보존한다 (`REQ-PWA-013`) | — |

스피너는 회전 1종(1.2s 등속)만 쓴다. `prefers-reduced-motion`에서도 유지한다 — 진행 중임을 알리는 필수 정보이기 때문이다. 대신 펄스·바운스·스켈레톤 shimmer 같은 장식 모션은 끈다.

### 1.6 아이콘·이미지·모션

- **아이콘**: Phosphor 단일 패밀리. `regular`(기본) · `fill`(활성 탭·체크 완료·북마크 켬) · `bold`(체크 마크). 이모지 0개. 운영에서는 필요한 아이콘만 골라 self-host 한다.
- **이미지**: 시안의 `picsum.photos`는 예시다. 운영은 권리 확인된 사진으로 교체하며, 사진 위 텍스트는 반드시 veil과 함께 쓴다(§3.2). `alt`는 장식 사진이면 빈 문자열, 내용이 있으면 설명을 적는다.
- **모션**: 시트 등장 220ms, 체크 전환 150ms, 버튼 누름 120ms, 토글 150ms. 이 네 가지가 전부다. `prefers-reduced-motion: reduce`에서 시트 애니메이션과 전환을 모두 끈다(시안이 이미 구현).

## 2. 컴포넌트

각 항목은 구조 → 치수 → 상태 → 접근성 순이다. 치수는 시안 CSS의 실제 값이다.

### 2.1 미션 카드 (`SCR-PWA-002`)

오늘 훈독 홈의 핵심. **훈독하기 · 기도하기 · 말씀 읽기** 3장이 세로로 쌓인다.

- **구조**: `[아이콘 칩 48×48] [종류·소요시간 / 제목 / 메타 줄] [체크 30×30]`
- **치수**: 카드 패딩 `14px 16px`, 요소 간격 14px, 카드 사이 12px. 아이콘 칩 `--surface-2` 배경 + `--ink-2` 아이콘 24px, 반지름 12px
- **타이포**: 종류 `micro` `--ink-3` / 제목 `body-lg` 600 / 메타 `meta-sm` `--ink-3`
- **상태**:
  - 미완료 — 체크는 `2px solid --ink-3` 빈 원
  - 완료 — 체크 배경 `--ok`, 흰 체크 아이콘, 아이콘 칩이 `--ok-soft` + `--ok-strong`으로 전환
  - hover(포인터) — 카드 배경 유지, 그림자 `--shadow-1`
- **접근성**: 카드 전체가 링크이고 체크는 별도 버튼이므로 **중첩 상호작용을 피한다.** 카드는 `<a>`, 체크는 카드 밖 형제 `<button>`으로 두고 시각적으로만 겹쳐 배치한다. 체크 버튼은 `aria-pressed`와 "훈독하기 완료" 같은 전체 문장 레이블을 갖는다. 완료 시 `role="status"` 토스트로 "훈독 완료 · 연속 13일"을 알린다
- **대비**: 제목 `--ink`/`--surface` **16.05:1**, 메타 `--ink-3`/`--surface` **5.35:1**, 완료 체크 흰 글자/`--ok` **5.23:1**, 미완료 체크 테두리 `--ink-3`/`--surface` **5.35:1**

### 2.2 말씀 카드 (`SCR-PWA-003`·`006`·`008`)

모든 말씀 표시의 기본 단위. **첫 줄이 반드시 출처**다 (`REQ-PWA-012`).

- **구조**: `[출처 줄] [인용 본문] [보조 행동]`
- **출처 줄** (`.src-line`): `micro` `--ink-3`, 항목 사이 3px 원형 구분자(`--line`), 줄바꿈 허용. 순서는 **화자 · 저작물 · 위치 · 판본 · 공식성 배지**. 미확인 항목은 생략하지 않고 "확인되지 않음"으로 적는다
- **인용 본문** (`.quote-official`): `quote` 16.5px/1.7, 왼쪽 `4px solid --ink` 선 + 왼쪽 패딩 14px, 상하 여백 12px. 검색 결과·근거 카드에서는 15px로 줄인다
- **인용 표시**: AI 설명 안의 근거 번호는 `<sup>` 숫자 + `--accent`. 숫자가 의미를 담으므로 색만으로 구분하지 않는다
- **접근성**: 카드 전체가 원문으로 가는 링크일 때 링크 텍스트는 인용문 전체가 아니라 `aria-label`로 "천성경 1편 3장 원문 열기"를 준다. 긴 인용문이 링크 이름이 되면 스크린 리더 탐색이 막힌다
- **대비**: 본문 `--ink`/`--surface` **16.05:1**, 출처 줄 `--ink-3`/`--surface` **5.35:1**, 검색 하이라이트 `--ink`/`--hl-1` **14.18:1** · `/--hl-2` **13.37:1** · `/--hl-3` **12.90:1**

### 2.3 권위 층 배지 (O1~O5 / R)

`REQ-PWA-012`와 PRD §7.1이 정한 규칙: **라벨 텍스트와 형태로 구분하고 색만으로 구분하지 않는다.**

**시안의 초록 배지를 그대로 유지한다** (2026-09-16 `DES-PWA-003-Q1` 확정). 정본(O1·O2)은 초록, 공식·보조(O3~O5)는 중립, 참고(R)는 점선이다.

| 등급 | 형태 | 배경 / 글자 | 테두리 | 라벨 예 | 대비 |
|---|---|---|---|---|---|
| O1 정본 | 초록 채움 | `--ok-soft` / `--ok-strong` | 없음 | `O1 공식 원문` | **6.14:1** |
| O2 공식 게시 | 초록 채움 | `--ok-soft` / `--ok-strong` | 없음 | `O2 공식 출처` | **6.14:1** |
| O3 공식 해설 | 중립 채움 | `--surface-2` / `--ink-2` | 없음 | `O3 공식 해설` | **6.33:1** |
| O4 역사 자료 | 중립 채움 | `--surface-2` / `--ink-2` | 없음 | `O4 1970년대 자료` | **6.33:1** |
| O5 지역 콘텐츠 | 중립 채움 | `--surface-2` / `--ink-2` | 없음 | `O5 교회 게시` | **6.33:1** |
| R 참고·미검증 | 아웃라인 점선 | 투명 / `--ink-2` | `1.5px dashed --ink-3` | `R 참고 자료` | **6.97:1** (paper) |

글자색만 `--ok`(4.49:1)에서 `--ok-strong`(6.14:1)으로 바꿨다. WCAG AA 4.5:1에 0.01 모자라서이며, 두 값은 화면에서 구분되지 않으므로 시안의 인상은 그대로다 (§6-2).

**색만으로 구분하지 않는 이유.** 형태 3단계(초록 채움 / 중립 채움 / 점선)는 **정본 · 공식 · 참고**만 가른다. O1과 O2, O3·O4·O5는 색과 형태가 같으므로 **등급 숫자와 한국어 라벨이 유일한 구분자**다. 따라서 등급 숫자만 단독으로 쓰지 않고 항상 한국어 라벨을 붙인다 — 시안에 `O1`만 적힌 곳이 있으나 "O1"이 무엇인지 아는 사용자가 전제되지 않는다.

- **치수**: 패딩 `3px 8px`, 반지름 8px, `micro-sm` 600, 아이콘 동반 시 간격 4px, 최소 높이 20px
- **초록이 두 가지 뜻을 갖는다.** 같은 화면에서 완료 체크와 O1 배지가 함께 보일 수 있다(예: 챌린지 상세의 "완료" 배지 + 말씀 카드의 `O1`). 혼동을 막는 장치는 **형태**다 — 완료는 항상 **체크 아이콘**을 동반하고, 등급은 항상 **등급 숫자 + 라벨 텍스트**를 갖는다. 체크 아이콘 없는 초록, 라벨 없는 초록을 만들지 않는다
- **권리 상태 배지**는 권위 등급과 다른 축이다. `일부` · `확인 중` · `철회됨`은 아웃라인 실선(`1px --ink-3`)에 `--ink-2` 글자를 쓰고, 등급 배지와 같은 줄에 두지 않는다
- **접근성**: 배지는 장식이 아니므로 `aria-hidden` 금지. 등급 설명을 처음 만나는 화면(서고·검색 결과 상단)에 "O1은 승인된 정본입니다" 같은 한 줄 안내를 둔다

### 2.4 순서지 (`SCR-PWA-010`)

이번 주 가정예배 순서. 번호가 붙은 6단계 목록이며 카드 하나 안에 들어간다.

- **구조**: `<ol>` 각 항목 = `[번호 원 26×26] [구분 / 제목 / 설명]`
- **치수**: 항목 패딩 `12px 0`, 항목 사이 `1px solid --line`, 마지막 항목은 선 없음. 번호 원 `--surface-2` 배경 + `--ink-2` `micro` 700
- **타이포**: 구분 `micro` `--ink-3` (예: "말씀 · 천성경 1편 3장") / 제목 `body` 600 / 설명 `caption` `--ink-2` 1.5
- **행동**: 카드 하단에 `가족에게 보내기`(채움) + `편집`(선). 공유는 가족 그룹 안으로 한정한다 (`AC-019-02`)
- **접근성**: 순서가 의미이므로 `<ol>`을 쓴다. 번호 원은 `aria-hidden`으로 두고 리스트 마커가 순서를 전달하게 한다
- **대비**: 제목 `--ink`/`--surface` **16.05:1**, 구분 `--ink-3`/`--surface` **5.35:1**, 번호 `--ink-2`/`--surface-2` **6.33:1**

### 2.5 챌린지 카드 (`SCR-PWA-010`·`011`)

진행률과 참여 인원만 보여준다. **개인 순위·점수를 넣지 않는다** (`DEC-PWA-019`).

- **요약 카드 구조**: `[제목 / D-day 배지] [진행 바] [완료일·퍼센트 / 참여 인원]`
- **진행 바**: 높이 8px, 트랙 `--surface-2`, 채움 `--accent`, 반지름 4px. 퍼센트를 **숫자로도 병기**한다(색·길이만으로 값을 전달하지 않는다)
- **모집 중 상태**: 진행 바 없이 시작일·예정 인원·개설자만 표시
- **상세 화면 통계**: 3등분 `stats` — 진행률(액센트 24px) / 완료한 날 / 남은 날. 라벨은 `micro` `--ink-3`
- **오늘 목록**: 참여자별 `[아바타] [이름 / 완료 시각] [완료 배지 또는 응원 버튼]`. 미완료는 "아직이에요"로 적고 부정적 표현·경고색을 쓰지 않는다 (`RSK-PWA-009`)
- **응원**: 사전 정의 3문구 칩만. 자유 입력창이 없다 (`AC-020-03`)
- **접근성**: 진행 바는 `role="progressbar"` + `aria-valuenow/min/max` + `aria-label="우리 가족 21일 훈독 진행률"`. 응원 버튼은 누른 뒤 `role="status"`로 결과를 알린다
- **대비**: 진행 바 채움 `--accent`/`--surface-2` **4.33:1** (비텍스트 3:1 통과), 진행률 숫자 `--accent`/`--surface` **4.98:1**, D-day 배지 `--accent-strong`/`--accent-soft` **5.73:1**

### 2.6 달력 (`SCR-PWA-011`·`014`)

미션 완료일을 보여주는 월/주 달력. 7열 그리드.

- **구조**: 요일 머리 7칸(`nano` `--ink-3`) + 날짜 칸. 날짜 칸 = `[상태 원 26×26] [날짜 숫자]` 세로 배치
- **상태 원**:
  - 미완료 — `1.5px solid --ink-3` 빈 원
  - 완료 — `--ok-soft` 배경 + `--ok-strong` 체크 아이콘 14px
  - 오늘 — 테두리 `--accent`, 날짜 숫자 `--accent` 700
  - 쉼(주 1회 면제) — `--surface-2` 배경 + "쉼" 텍스트 `--ink-3`
- **접근성**: 표가 아니라 목록이므로 `<table>` 대신 그리드를 쓰되 각 칸에 "9월 8일 완료" 같은 전체 문장 레이블을 준다. 완료는 색이 아니라 **체크 아이콘**이, 쉼은 **"쉼" 글자**가 1차 신호다
- **대비**: 완료 체크 `--ok-strong`/`--ok-soft` **6.14:1**, 오늘 테두리 `--accent`/`--surface` **4.98:1**, 날짜 숫자 `--ink-2`/`--surface` **7.27:1**, 미완료 테두리 `--ink-3`/`--surface` **5.35:1**
- 달력 칸은 시안에서 비상호작용이다. 탭 가능하게 만들면 각 칸이 최소 24×24를 넘어야 한다(§3.5)

### 2.7 바텀 시트 (`SCR-PWA-004`, 용어 시트)

- **구조**: 반투명 배경막 `rgba(35,33,31,0.45)` + 하단 정렬 패널
- **치수**: 상단 모서리 28px, 패딩 `10px 20px 28px`, 최대 높이 88%, 내부 스크롤. 상단 그립 40×5px `--line`
- **등장**: 220ms `translateY(24px)` → 0 + opacity. `prefers-reduced-motion`에서 애니메이션 제거
- **닫기**: 배경막 탭, 닫기 버튼, **Esc 키**. 시안은 앞의 둘만 있으므로 Esc를 추가한다
- **접근성**: `role="dialog"` + `aria-modal="true"` + `aria-labelledby`(시트 제목). 열릴 때 포커스를 시트 안 첫 요소로 옮기고, 닫힐 때 여는 버튼으로 되돌린다. 열린 동안 배경 스크롤과 포커스를 가둔다. 그립은 `aria-hidden`

### 3.2 사진 위 텍스트

사진은 내용을 통제할 수 없으므로 **최악의 경우(순백 사진)를 기준으로 계산한다.**

veil은 **정지점 3개**를 쓴다. 텍스트가 놓이는 하단 구간 전체에서 알파가 0.80 이상이어야 하기 때문이다.

```css
background: linear-gradient(180deg,
  rgba(35,33,31,0)    18%,
  rgba(35,33,31,0.80) 55%,
  rgba(35,33,31,0.92) 100%);
```

순백 사진 최악 조건의 계산값과, 예시 사진에서 실제로 렌더해 픽셀 단위로 측정한 값이다.

| 요소 | 실효 배경 | 최악(순백) 계산 | 실측 (예시 사진) | 판정 |
|---|---|---|---|---|
| 인사 문장 상단 (흰 글자 100%) | `#4f4d4c` | **8.37:1** | 9.71:1 | 통과 |
| 인사 문장 하단 (흰 글자 100%) | `#42403e` | **10.32:1** | — | 통과 |
| 보조 줄 (흰 글자 92%) | `#353331` | **10.95:1** | 10.05:1 | 통과 |
| 설교 썸네일 시간 배지 (흰 글자 / `rgba(0,0,0,0.7)`) | `#4d4d4d` | **8.45:1** | — | 통과 |

규칙 네 가지.

- 텍스트는 **veil 알파가 0.80 이상인 구간**(사진 하단 45%)에만 배치한다. 사진 상단에 텍스트를 올리지 않는다.
- **단일 정지점 그라데이션(`0 → 0.78 100%`)을 쓰지 않는다.** 알파 0.78은 사진 맨 아래 한 줄에서만 성립하고 텍스트 구간 대부분은 그보다 옅다. 데스크톱 시안을 그리기 전까지 이 문서가 갖고 있던 오류다 (§4.6).
- 보조 줄의 글자 불투명도를 0.85 아래로 내리지 않는다. 0.85면 최악 조건에서 한계선에 붙는다.
- 사진 로드 실패 시 `--surface-2` 배경이 남는데, 이때 흰 글자는 1.15:1로 읽히지 않는다. **사진 컨테이너의 기본 배경색을 `--ink`로 둔다.**

### 3.4 200% 확대와 리플로

- 뷰포트 메타에 `maximum-scale`·`user-scalable=no`를 넣지 않는다 (시안이 이미 `width=device-width, initial-scale=1`만 쓴다).
- 모든 글자 크기·행간·여백은 `rem`으로 쓴다. `px` 고정 글자 크기는 브라우저 글자 크기 설정을 무시한다.
- **높이 고정 금지.** 텍스트를 담는 컨테이너에 `height`를 주지 않고 `min-height`를 쓴다. 대상: 앱바(52px), 탭바(84px), 버튼(50px), 미션 카드, 배지, 요일 칩.
- **탭바**는 200%에서 라벨이 2줄이 되도록 허용하고 높이가 자라게 한다. 라벨을 지우고 아이콘만 남기지 않는다(§2.8).
- **가로 스크롤 금지.** 390px × 200% 확대에서 본문이 가로로 넘치지 않아야 한다. 예외는 자체 가로 스크롤 컨테이너를 가진 세 가지뿐이다: 교회장 아바타 행, 판본 나란히 보기, 긴 표.
- **판본 나란히 보기**는 확대 시 2열을 유지할 수 없으므로 **세로 교차 배치**(판본 A 단락 → 판본 B 같은 단락)로 떨어뜨린다.
- `.title-lg` 26px 같은 큰 글자는 확대 시 줄바꿈이 어색해지므로 `text-wrap: balance`를 적용한다.

### 3.5 탭 대상 크기 (WCAG 2.2 SC 2.5.8, AA)

최소 24×24 CSS px. 시안에서 미달인 곳은 **용어 칩 하나**다(패딩 `2px 8px` + 12.5px 글자 ≈ 23px). 최소 높이 24px을 명시하고, 본문 안에 연달아 놓을 때는 세로 간격 8px 이상을 둔다.

통과 확인: 아이콘 버튼 40×40 · 탭 항목 78×76 · 체크 30×30(목록 안 24×24) · 요일 칩 34×34 · 칩 버튼 ≈40 · 토글 46×28 · 버튼 50 · 리더 바 항목 ≈76×40 · 라디오 행 48+.

## 4. 데스크톱 브레이크포인트

**같은 컴포넌트의 반응형 규칙으로만 처리한다.** 데스크톱 전용 화면·라우트·정보구조를 만들지 않는다.

| 이름 | 범위 | 성격 |
|---|---|---|
| `base` | < 768px | 폰. 단일 컬럼, 화면 폭 100%, 좌우 거터 20px, 하단 5탭 |
| `md` | 768~1023px | 태블릿·가로 폰. 단일 컬럼 중앙 정렬, 하단 5탭 유지, 일부 목록 2열 |
| `lg` | ≥ 1024px | 데스크톱. 좌측 레일, 중앙 정렬 본문, 원문 뷰 2-pane, 시트→모달, hover 활성 |

브레이크포인트는 **3개로 끝이다.** 1440px 이상에서 추가 변화를 넣지 않는다 — 레일과 본문이 고정 폭이라 남는 공간은 좌우 여백으로 흡수된다. 4번째 단계를 넣으면 검증 조합이 늘고 드리프트가 생긴다.

### 4.1 하단 5탭 → 좌측 사이드 레일: 1024px

**전환 지점을 1024px로 잡은 근거는 기하학이다.**

레일 240px + 본문 720px + 좌우 최소 여백 32px × 2 = **1024px**. 768px에서 레일을 꺼내면 본문이 464px로 눌려 원문 뷰의 읽기 폭(640px)을 확보할 수 없다. 관례가 아니라 이 앱의 실제 폭에서 나온 숫자다.

768~1023px에서 하단 탭을 유지하는 이유는 하나 더 있다. 이 구간의 기기는 대부분 터치 입력이고, 하단 탭은 엄지 도달을 위한 형태다. 포인터가 확실해지는 지점에서만 바꾼다.

**레일 규격** (≥1024px)

- 폭 240px, 좌측 고정(`position: sticky; top: 0; height: 100dvh`), 배경 `--surface`, 우측 `1px solid --line`
- 상단에 앱 이름 "훈독" + 베타 표기, 그 아래 5항목 세로 목록
- 항목: `[아이콘 24px] [라벨 body]`, 패딩 `12px 16px`, 반지름 12px, 간격 4px. 최소 높이 48px
- 비활성 `--ink-2`, hover 배경 `--surface-2`, 활성 배경 `--accent-soft` + 글자 `--accent-strong` + `fill` 아이콘
- **중앙 돌출 버블은 레일에서 사라진다.** 세로 목록에 매달린 원형 버블은 형태가 성립하지 않는다. 대신 "말씀" 항목의 **아이콘만 40×40 `--accent` 채움 칩**에 담아 중심 강조를 전한다. 라벨과 배경은 다른 항목과 같다
- **항목 배경을 채우는 것은 활성 상태뿐이다.** 초안은 "말씀"을 항상 `--accent` 채움 pill로 두려 했으나, 그리고 보니 다른 항목과 같은 pill 형태라 **"선택됨"으로 읽혔다**(§4.6). 모바일에서는 버블이 원형으로 튀어나와 형태가 달랐기 때문에 문제가 없었다
- 아이콘·라벨·활성 표시 규칙은 탭바와 동일하다. 항목 순서·명칭·라우트가 같으므로 **탭 정의는 한 곳(라우트 목록)에서 가져다 두 형태로 렌더한다.** 두 벌로 적지 않는다
- 하단 탭바는 ≥1024px에서 `display: none`이 아니라 렌더 자체를 하지 않는다(중복 landmark 방지)
- 대비: 활성 `--accent-strong`/`--accent-soft` **5.73:1**, 비활성 `--ink-2`/`--surface` **7.27:1**

### 4.2 본문 폭

| 이름 | 값 | 적용 |
|---|---|---|
| 앱 콘텐츠 폭 | **720px** | 카드·리스트·폼·히어로. `md` 이상에서 중앙 정렬 |
| 읽기 폭 | **640px** | 원문 단락(`.verse`), 공식 원문 인용, AI 설명 본문, 긴 산문 |

읽기 폭 640px의 근거: 원문 단락은 17px 한글이고 전각 문자 폭이 약 17px이므로 640px에서 한 줄 약 37자다. 한글 본문의 편안한 범위(35~45자) 안이다. 390px에서는 약 20자이므로 확대 폭은 두 배 이내다.

카드·리스트에 720px을 따로 두는 이유: 카드 안은 `[아이콘][본문][체크]` 3단 가로 배치라 640px에서는 본문 열이 좁아진다. 산문과 카드에 같은 폭을 강요하면 한쪽이 나빠진다.

**두 폭을 한 화면에 섞지 않는다.** 화면 단위로 하나를 고른다.

| 폭 | 화면 | 이유 |
|---|---|---|
| **640px** (컬럼 전체) | `003` 훈독하기 · `006` 질문·답변 상세 · `009` 원문 뷰 | 화면 전체가 읽기 콘텐츠다. 720px 컬럼 안에 640px 블록을 섞으면 섹션 제목과 카드의 오른쪽 끝이 어긋나 지저분해진다 (§4.6) |
| **720px** (컬럼 전체) | 나머지 13화면 | 카드가 3단 가로 배치이거나 그리드다 |

**앱바 내부 폭은 그 화면의 콘텐츠 폭과 같다** — 720 / 640 / 952(2-pane: 280 + 32 + 640). 앱바를 720px로 고정하면 2-pane 화면에서 제목·배지가 본문과 어긋난다 (§4.6).

`base`에서는 두 값 모두 적용되지 않는다(폭 100%, 거터 20px).

### 4.3 SCR-PWA-007 / 008 / 009 의 2-pane 여부

| 화면 | 2-pane | 근거 |
|---|---|---|
| `SCR-PWA-007` 말씀 서고 | **아니오** | 모바일에서 저작물을 탭하면 권·장 목차로 **이동**한다. 데스크톱에서 목차를 옆 창에 상시 노출하면 모바일에 없는 계층이 하나 생기고, 뒤로가기의 의미가 두 벌이 된다. 대신 저작물 목록과 바로가기 4종을 **2열 그리드**로 펼친다 — 같은 컴포넌트의 배치 변경이다 |
| `SCR-PWA-008` 말씀 검색 | **아니오** | 결과를 탭하면 원문 뷰로 이동하는 흐름이 모든 폭에서 같아야 한다. 오른쪽에 미리보기 창을 만들면 "결과를 연다"는 동작이 폭에 따라 다른 뜻이 된다. 단일 컬럼 유지, "이렇게도 찾을 수 있어요" 블록은 결과 아래 그대로 |
| `SCR-PWA-009` 원문 뷰 | **예** | 모바일에서도 리더 바의 "목차"가 **이미 오버레이로 존재한다.** 데스크톱은 그 오버레이를 상시 노출로 바꾸는 것이라 새 계층이 아니다. 더해 판본 나란히 보기는 본질적으로 2열이고 640px 아래에서는 실용적이지 않다 |

**원문 뷰 2-pane 규격** (≥1224px)

목차 레일은 `lg` 전체가 아니라 **1224px 이상**에서만 노출한다: 내비 레일 240 + 목차 280 + 본문 640 + 좌우 여백 32×2 = **1224px**. 1024~1223px에서는 목차 레일을 접고 툴바의 "목차" 버튼(모바일과 같은 오버레이)으로 되돌린다.

이것은 **네 번째 전역 브레이크포인트가 아니다.** `lg` 안에서 이 컴포넌트 하나에만 적용하는 min-width이며, 다른 화면은 1024px부터 `lg` 규칙을 그대로 쓴다.

- 좌: 목차 레일 280px — `position: sticky`, 현재 장 강조(배경 `--accent-soft` + `--accent-strong`), 내부 스크롤
- 우: 본문 640px — 본문/AI 설명/노트 pill 세그먼트는 본문 상단에 그대로
- 하단 리더 바(형광펜·노트·북마크·목차·설정)는 **본문 컬럼 상단의 가로 툴바로 이동**한다. 목차 항목은 레일이 이미 보이므로 제외한다
- 오디오 바는 본문 컬럼 상단에 고정
- 판본 나란히 보기를 켜면 본문 컬럼이 640px 2열(합계 1296px)이 되어 레일을 접는다. 이 한 가지가 레일이 접히는 유일한 경우다

### 4.4 나머지 13화면

기본은 **단일 컬럼 중앙 정렬**이다. 예외 셋과 각각의 근거.

1. **바텀 시트 → 중앙 모달** (`SCR-PWA-004`, 용어 시트). 하단 시트는 엄지 도달을 위한 형태이고 포인터 환경에서는 근거가 사라진다. 콘텐츠·상태·닫기 동작은 동일하다 (§2.7)
2. **FAB 위치를 콘텐츠 컬럼 기준으로** (`SCR-PWA-005`). 뷰포트 오른쪽에 붙이면 본문에서 멀어져 어느 목록의 버튼인지 알 수 없다 (§2.9)
3. **2열 그리드 허용 목록** — 말씀 서고의 저작물 목록·바로가기 4종(`007`), 설교 목록(`012`), 교회장 아바타 행(`012`, 가로 스크롤 대신 줄바꿈). 모두 **순서 없는 병렬 항목**이라 2열로 펼쳐도 읽는 순서가 바뀌지 않는다. 미션 카드 3장(`002`)·순서지 6단계(`010`)·검색 결과(`008`)는 순서가 의미이므로 2열로 만들지 않는다

### 4.5 데스크톱 상호작용

시안에는 `:active`와 입력 `:focus`만 있었다. 포인터 환경에서 필요한 것을 §1.5에 정의했고 데스크톱 시안으로 확인했다.

| 대상 | hover |
|---|---|
| 채움 버튼 · FAB | 배경 `--accent` → `--accent-strong` (흰 글자 6.74:1) |
| 연한 버튼 · 칩 · 리스트 항목 · 레일 항목 · 툴바 버튼 | 배경 → `--surface-2` |
| 카드 링크 | `--shadow-hairline` → `--shadow-1`. 이동·확대 없음 |
| 활성 레일 항목 · 활성 목차 항목 | 배경 유지(`--accent-soft`). 활성 항목에 hover 변화를 주면 선택 상태가 흔들린다 |

hover 규칙은 전부 `@media (hover: hover)` 안에 둔다. 터치 기기에서 hover 스타일이 탭 뒤에 남는 것을 막는다.

### 4.6 데스크톱 시안이 잡아낸 규칙 오류

§4를 글로만 쓴 뒤 실제로 그려 보니 **다섯 가지가 틀렸다.** 모두 이 문서에 반영했고, 시안 HTML이 반영 결과다.

| # | 글로 썼던 규칙 | 그려 보니 | 고친 곳 |
|---|---|---|---|
| 1 | 2-pane은 `lg`(≥1024px) 전체 | 240 + 280 + 640 + 여백 64 = **1224px**이 필요하다. 1024px에서는 목차와 본문이 들어가지 않는다 | §4.3 |
| 2 | 카드 720px + 그 안의 산문 640px | 섹션 제목(720)과 카드(640)의 오른쪽 끝이 어긋나 지저분하다. **화면 단위로 한 폭**을 고른다 | §4.2 |
| 3 | (규정 없음) | 앱바를 720px로 고정하면 2-pane 화면에서 제목이 본문과 어긋난다. **앱바 폭 = 그 화면의 콘텐츠 폭** | §4.2 |
| 4 | "말씀"을 `--accent` 채움 pill로 | 다른 항목과 같은 pill이라 **"선택됨"으로 읽힌다**. 아이콘 칩으로 바꾸고 배경은 활성 상태에 넘긴다 | §4.1 |
| 5 | 사진 veil `0 → 0.78 100%` | 알파 0.78은 맨 아래 한 줄에서만 성립한다. 텍스트 구간은 그보다 옅어 규칙을 만족할 수 없다. **정지점 3개**로 바꾼다 | §3.2 |

렌더 검증: Chromium 11캡처(1280px 8화면 + 1180 · 1024 · 1440), 가로 넘침 0px, 콘솔 오류 0. 사진 위 대비는 캡처 픽셀을 직접 읽어 측정했다(§3.2).

> 다섯 번째는 시안 HTML에서도 한동안 드러나지 않았다. 모달 배경막에 `.veil`이라는 같은 클래스를 써서 `display:none`이 사진 veil까지 꺼 버렸고, 사진 자체의 어두운 하단이 veil처럼 보였기 때문이다. **눈으로 보는 대신 픽셀을 측정해서** 찾았다. 대비는 눈짐작으로 판정하지 않는다.

## 6. 시안과 달라지는 것

시안이 정본이지만 네 곳은 확정 결정·WCAG 기준과 충돌해 바꿨다. **이 네 개 외에 임의 변경은 없다.**

| # | 시안 | 이 문서 | 강제한 근거 |
|---|---|---|---|
| 1 | 5번째 탭 "나의 뜰" | **"나의 정원"** | `DEC-PWA-015` (2026-09-14 확정). 시안은 09-10 산출물이라 재생성하지 않는다 |
| 2 | `--accent` on `--accent-soft` = 4.23:1, `--ok` on `--ok-soft` = 4.49:1 | `--accent-strong #a03a1a` (5.73:1), `--ok-strong #26633f` (6.14:1) 추가 | WCAG 2.2 AA 본문 4.5:1 미달. 배지·용어 칩·선택 옵션이 11.5~12.5px이라 큰 글자 예외(18.66px bold)에 해당하지 않는다. 두 값은 같은 색상(hue)의 어두운 단계이므로 "액센트 1색" 규칙을 깨지 않는다 |
| 3 | 체크·라디오·토글 off·입력 테두리 `--line` (1.30:1) | `--ink-3` 테두리 (5.35:1) | WCAG 1.4.11 비텍스트 대비 3:1. 상태를 테두리로만 알리는 컨트롤이 대상이며, 카드·구분선 같은 장식 경계는 `--line`을 그대로 쓴다 |
| 4 | 용어 칩 높이 약 23px | 최소 높이 **24px** | WCAG 2.2 SC 2.5.8 (AA) 최소 탭 대상 24×24 |
**O1·O2 배지의 초록은 시안 그대로 둔다.** 2026-09-16 사용자 결정(`DES-PWA-003-Q1`)이다. 초록을 완료 전용으로 좁히는 대안은 검토했으나 채택하지 않았다. 대신 `--ok`가 **완료**와 **정본 등급** 두 의미를 갖는다는 점을 §1.1 색 규칙과 §2.3에 명시하고, 형태(체크 아이콘 / 등급 라벨)로 혼동을 막는다. 글자색 `--ok` → `--ok-strong` 교체는 위 2번(대비 미달 해소)에 포함된다.

바꾸지 않은 것 중 기록해 둘 것 하나. 시안의 `.serif-quote`(20px) 규칙은 A 마크업에서 한 번도 쓰이지 않는 죽은 선언이라 옮기지 않았다. B의 세리프 인용을 흡수하려던 흔적이며 `DEC-PWA-017`이 미채택했다.

## 7. S5 구현 인계

### 7.1 먼저 만들 것

1. 토큰 정의(§1)를 CSS 사용자 지정 속성 한 파일로. `apps/web` 안에 두되 기존 `globals.css`의 시연 웹 테마와 **선택자 범위를 분리**한다 (`UI-WEB-001` 보존).
2. 컴포넌트 10종(§2)을 토큰만 참조해 구현. 하드코딩된 색·크기 0개.
3. 탭 정의(라벨·아이콘·라우트) 단일 목록 → 탭바와 레일 두 형태로 렌더 (§4.1).
4. 반응형은 3 브레이크포인트(§4)만. 컴포넌트 안에서 미디어 쿼리를 쓰고 화면별 분기를 만들지 않는다.

### 7.2 하지 말 것

- 다크 팔레트 정의 (베타 라이트 고정)
- 데스크톱 전용 라우트·컴포넌트·레이아웃 파일
- 공통 UI 패키지 승격 (`APP-UI-001`)
- `apps/web/src/app/design-system` 수정 (기존 시연 웹 전시물)
- 네 번째 브레이크포인트 추가
